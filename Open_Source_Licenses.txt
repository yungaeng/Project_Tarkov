상업 배포용 제3자 고지 및 확인 사항
작성일: 2026-11-11 (Asia/Seoul)

에셋 교체 계획과 진행 상태: docs/licenses/README.md (2026-11-11 별도 분류)
현재 교체는 미완료이며 아래 원문 고지와 권리 확인 항목은 유지한다.

1. 범위와 현재 상태
이 문서는 게임 전체에 MIT 등 하나의 라이선스를 부여하지 않는다.
직접 작성한 코드의 배포 조건, 제3자 소프트웨어 조건, 에셋 사용 허가는 각각 별개다.
현재 상태: 라이브러리 고지 원문은 아래에 수록했지만 에셋 권리 확인은 미완료다.
이 문서를 포함하는 것만으로 게임 전체의 상업 배포가 허가되는 것은 아니다.

근거: vcpkg.json, vcpkg_installed/vcpkg/status,
vcpkg_installed/x64-windows/share/<package>/copyright 및 소스/에셋 메타데이터.
manifest baseline: f26ec398c25c4980f33a50391f00a75f7ad62ef7
설치 패키지 기준으로 직접/간접 의존성을 보수적으로 포함했다.
실제 출시 바이너리의 링크/DLL 목록은 이번 작업에서 검사하지 않았다.
버전 변경이나 배포 파일 변경 시 고지 원문과 NOTICE를 다시 대조해야 한다.

2. 소프트웨어 사용 및 고지
- 직접 의존성: GLAD(MIT 및 생성 코드 관련 고지), GLFW(zlib/libpng),
  GLM(MIT 또는 수정 MIT), Dear ImGui(MIT), Assimp(BSD 계열 및 포함 코드 고지),
  stb(MIT 또는 public-domain 대안). 구체적인 선택지/조건은 아래 원문을 따른다.
- Assimp 간접 의존성: Draco(Apache-2.0 및 동봉 제3자 고지), poly2tri(BSD),
  kubazip(MIT), minizip/zlib(zlib 계열), polyclipping(Boost Software License),
  pugixml(MIT), RapidJSON(MIT 및 포함 코드 고지), utfcpp(Boost Software License).
- MIT/BSD: 적용 대상 저작권·허가·면책 문구를 보존한다. BSD의 보증/추천 금지 조건도 준수한다.
- zlib: 출처를 허위 표시하지 않고 변경 소스는 구분하며 소스 고지를 제거하지 않는다.
- Apache-2.0: 라이선스 사본, 변경 파일 표시, 관련 고지를 유지한다.
  원 배포물에 NOTICE가 있으면 해당 내용도 배포 형태에 맞게 포함한다.
- 본 문서에는 선택적 라이선스 대안도 삭제하지 않고 패키지 제공 원문대로 수록했다.
- vcpkg-cmake 계열은 빌드 도구 고지이며 런타임 DLL이라는 의미가 아니다.
- 이 permissive 라이선스들은 그 자체로 게임 전체 소스 공개를 요구하지 않는다.
  고지 보존 등 각각의 조건을 지키는 상업/비공개 소스 사용을 전제로 한다.

3. 개발 도구·Windows 구성 요소
C++는 언어이며 자체 게임 매출 로열티 대상이 아니다. 컴파일러/SDK는 별도 약관을 따른다.
Visual Studio 설치 에디션과 사용자/조직의 자격은 이번에 확인하지 않았다.
Community의 개인 개발 사용과 조직 사용 자격은 구분해서 확인해야 한다.
https://www.microsoft.com/licensing/guidance/Visual-Studio

개발·테스트 경로 x64/Debug는 유지한다. 출시 배포 시에는 별도 Release 패키지를 준비하고
Microsoft의 허용된 VC++ Redistributable을 사용한다. debug_nonredist의 Debug 런타임을
일반 고객용 게임에 복사해서 배포하지 않는다. 이번 작업에서 빌드 설정은 변경하지 않았다.
https://learn.microsoft.com/visualstudio/releases/2022/redistribution
https://learn.microsoft.com/cpp/windows/latest-supported-vc-redist

OpenGL API를 사용한 게임 개발에 별도 API 사용 로열티는 없지만,
드라이버/구현 라이브러리와 Khronos 헤더의 권리·상표 조건은 별개다.
https://www.khronos.org/about
XAudio2/Windows SDK는 Windows 플랫폼 구성 요소다. OS DLL을 임의로 묶어 배포하지 말고
대상 Windows 버전 및 SDK의 재배포 조건을 따른다.

폰트: src/Game/UI/RaidHud.cpp는 사용자 Windows의 malgun.ttf 또는 gulim.ttc를 읽는다.
현재 방식은 설치된 시스템 폰트 사용이다. 이 폰트 파일을 게임 Assets에 복사해 배포할 권리는
별도로 확인해야 한다. 문서 임베딩 허가를 게임 폰트 재배포 허가로 해석하지 않는다.
https://learn.microsoft.com/en-us/typography/fonts/font-faq

4. 에셋 — 상업 배포 전 해결할 항목
[A: 권리 확인 미완료] Assets/Models/Player/Male 및 여캐의 character.mesh / character.png
ArtSource/Characters/*/Derived/import.json의 source에 Koikatsu/Export_PMX 경로가 기록되어 있다.
해당 게임/캐릭터 카드/모드/텍스처 권리자의 상업 사용·변형·게임 내 재배포 허가를 확보하거나
명확히 허가된 대체 에셋으로 교체해야 한다. 직접 변환·가공했다는 사실만으로 원본 권리가
사라지지 않는다. 현재 저장소에서 해당 허가 증빙을 확인하지 못했다.

[B: 제한 메타데이터 확인] ArtSource/Characters/SurvivorHead/KoreanSurvivor.vrm
실제 VRM JSON 메타데이터:
  authors: ["kys10"]
  licenseUrl: https://vrm.dev/licenses/1.0/
  avatarPermission: onlyAuthor
  commercialUsage: personalNonProfit
  allowRedistribution: false
  modification: prohibited
  creditNotation: required
  allowExcessivelyViolentUsage: false
  allowExcessivelySexualUsage: false
head_attachment.json에는 게임 모델에 머리를 결합한 기록이 있다.
현재 메타데이터를 제3자 상업 이용 허가로 볼 수 없다. authors에 사용자 이름이 있더라도
외부 파츠/텍스처까지 권리 보유를 증명하지는 않는다. 본인이 모든 필요한 권리를 보유한 경우
출시 용도에 맞는 허가 근거와 메타데이터를 정리한다. 이번 작업에서는 이를 변경하지 않았다.

[C: 입수 경로 확인 필요] Assets/Models/Player/Ch22_nonPBR.fbx 및
Assets/Animations/Characters/Locomotion/*.fbx (Idle, Walking, Fast Run, Crouched Walking)
파일명만으로 Mixamo 정식 취득을 확정할 수 없다. 원 다운로드 출처·취득 기록을 보관한다.
Adobe FAQ는 Mixamo 캐릭터/애니메이션의 상업 게임 이용을 허용한다. 단, 가져온 외부 모델의
권리까지 부여하지는 않으며 원본 파일을 별도 에셋 상품으로 재판매하는 허가로 해석하지 않는다.
https://helpx.adobe.com/creative-cloud/faq/mixamo-faq.html
https://wwwimages2.adobe.com/content/dam/cc/en/legal/servicetou/Mixamo-Addl-Terms-en_US-20210623.pdf

[D: 생성/참조 기록 확인] Assets/UI/items.png
Assets/UI/README.md는 image_gen 생성과 사용자 제공 상품 참조 이미지 편집을 기록한다.
생성 시 적용 서비스 약관과 참조 이미지 이용 권한을 확인·보관한다.
이 파일을 MIT 에셋으로 간주하지 않는다. 생성 서비스 사용만으로 참조물의 권리가 해결되지는 않는다.

[E: 프로젝트 제작 자료]
Weapons/*.obj는 프로젝트 제작을 명시한 주석이 있으며, .anim/.layout/.parts/셰이더,
절차 생성 의상·총소리 등도 프로젝트 소스에 구현되어 있다.
외부 자료에서 파생된 부분이 있다면 원 자료 권리를 별도로 확인한다.
게임 제목·상표·로고·제품 외형의 이용 허가는 소프트웨어 라이선스와 별개다.

[F: 기존 Tripo AI & Stability AI MIT 고지]
원래 이 파일에 있던 고지를 마지막에 그대로 보존했다.
그 고지가 적용되는 실제 코드/모델/도구의 대응 관계는 저장소에서 확인하지 못했다.
특정 생성 결과물이나 위 캐릭터 전체가 MIT라는 근거로 사용하지 않는다.

Python/NumPy/Pillow는 Tools의 제작용 의존성이다. 게임과 함께 도구/인터프리터/패키지를
배포한다면 그 배포 버전의 라이선스도 추가해야 한다. 이번 런타임 패키지 목록에는 포함하지 않았다.

5. 배포 준비 및 갱신
- 본 문서를 게임 배포물에 포함하고, 외부 고지/NOTICE 요구 사항을 유지한다.
- 실제 출시 패키지의 DLL·정적 링크·헤더 코드·에셋과 이 목록을 다시 대조한다.
- 위 A~D의 미확인 권리를 해결한 뒤 해당 증빙과 출처를 기록한다.
- 공개 저장소에 올리는 원본 에셋도 재배포에 해당할 수 있으므로 허가 범위를 확인한다.
- 라이브러리나 에셋 교체 시 해당 버전의 원문으로 갱신한다.
- 이번에는 문서만 작성했다. 빌드/테스트/배포는 수행하지 않았다.

6. 설치 패키지 목록 및 원문 고지
아래 원문은 로컬 설치 패키지에서 직접 복사했다. 요약보다 원문 조건이 우선한다.

Introduction
---------------------
MiniZip 1.1 is built from MiniZip 1.0 by Gilles Vollant ( http://www.winimage.com/zLibDll/minizip.html )

When adding ZIP64 support into minizip it would result into risk of breaking compatibility with minizip 1.0.
All possible work was done for compatibility.


Background
---------------------
When adding ZIP64 support Mathias Svensson found that Even Rouault have added ZIP64 
support for unzip.c into minizip for a open source project called gdal ( http://www.gdal.org/ )

That was used as a starting point. And after that ZIP64 support was added to zip.c
some refactoring and code cleanup was also done.


Changed from MiniZip 1.0 to MiniZip 1.1
---------------------------------------
* Added ZIP64 support for unzip ( by Even Rouault )
* Added ZIP64 support for zip ( by Mathias Svensson )
* Reverted some changed that Even Rouault did.
* Bunch of patches received from Gulles Vollant that he received for MiniZip from various users.
* Added unzip patch for BZIP Compression method (patch create by Daniel Borca)
* Added BZIP Compress method for zip
* Did some refactoring and code cleanup
