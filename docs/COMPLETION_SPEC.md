# 프로젝트 완성 스펙

작성일: 2026-10-08
상태: 소규모 완성 버전을 위한 제안 기준. 콘텐츠 수량과 게임 규칙은 구현 전 조정할 수 있습니다.

## 1. 목표

싱글플레이 타르코프형 게임의 소규모 완성 버전을 목표로 합니다.
다음 흐름을 처음부터 끝까지 화면에서 조작하고 반복할 수 있어야 합니다.

**장비 준비 → 레이드 입장 → 탐색·전투·파밍 → 탈출 또는 사망 → 결과 정산 → 창고 저장**

우선 맵 1개, 총기 1종, 적 1종으로 전체 흐름을 완성한 뒤 콘텐츠를 확장합니다.

## 2. 현재 상태와 검증 한계

이동·충돌·중력·웅크리기·애니메이션·아이템 줍기·기본 인벤토리는 코드에 구현되어 있습니다.
최근 변경은 사용자 요청에 따라 빌드·실행하지 않았으므로 실제 동작 검증이 남아 있습니다.
구현됨과 검증 완료를 구분하며, 정적 검토만으로 플레이 가능 상태를 확정하지 않습니다.

- 현재 구조: [STRUCTURE.md](STRUCTURE.md)
- 아이템과 인벤토리: [INVENTORY.md](INVENTORY.md)
- 다음 작업 상세: [NEXT_TASK_SPEC.md](NEXT_TASK_SPEC.md)

| --- | --- | --- |
| 기본 조작 | 이동, 달리기, 웅크리기, 상호작용, 카메라 충돌 | 현재 3인칭 유지 |
| 아이템 | 줍기, 사용, 버리기, 묶음, 상세 정보 | 회복·음료·탄약·전리품 |

| 사운드 | 발소리, 총성, 피격, 재장전, 상호작용 | 기본 효과음 |

총기 발사 속도·피해량·탄창 크기, AI 감지 거리·명중률, 레이드 시간·탈출 대기 시간,
스태미나 소비·회복량, 목표 하드웨어·해상도·프레임률은 각 단계 상세 설계에서 정합니다.
이 문서는 해당 수치가 이미 확정되었다고 가정하지 않습니다.

## 4. 게임 규칙 제안

저장과 아이템 소유권 구현 전에 아래 규칙을 기준으로 확정합니다.

| 상황 | 제안 규칙 |
| --- | --- |
| 탈출 성공 | 출격 장비와 획득 아이템을 창고로 반환 |
| 사망·시간 초과 | 레이드에 가져간 장비와 획득 아이템 상실 |
| 강제 종료 | 진행 중 레이드를 실패로 처리 |
| 재출격 | 장비가 전부 없어도 기본 장비로 다시 플레이 가능 |
| 사용·이동 실패 | 아이템과 플레이어 상태를 변경하지 않음 |
| 결과 정산 | 재실행하거나 결과 화면을 반복해도 보상을 중복 지급하지 않음 |

창고와 레이드가 같은 아이템을 동시에 소유하지 않도록 이동 시점을 명확히 합니다.
정산은 한 번만 반영하고, 저장 실패 시 성공한 것처럼 안내하지 않아야 합니다.
기본 장비의 구성과 반복 지급에 따른 악용 방지는 창고 단계에서 상세 규칙을 정합니다.

## 5. 구현 순서와 단계별 완료 기준

### 1단계: 현재 기능 검증과 조작 완성

- 최근 구조 변경, 웅크리기 충돌, 줍기·인벤토리를 확인합니다.
- 카메라의 벽 관통 방지와 상호작용 안정화를 진행합니다.
- 완료 기준: 이동·자세·카메라·입력 전환이 일관되고 벽 너머 줍기가 차단됩니다.

### 2단계: 아이템 사용·버리기와 플레이어 상태

- 안전한 버리기·재줍기, 체력·수분·스태미나, 회복을 구현합니다.
- 즉시 진행할 아이템 작업은 [NEXT_TASK_SPEC.md](NEXT_TASK_SPEC.md)를 따릅니다.
- 해당 상세 문서의 첫 작업에서는 체력·수분까지만 다루며 스태미나는 후속 작업으로 추가합니다.
- 완료 기준: 아이템 사용 효과가 적용되고, 실패·연속 입력·재줍기에도 수량이 보존됩니다.

### 3단계: 무기와 전투

- 총기 1종의 장착·조준·발사·명중·피해·반동·재장전·사망을 연결합니다.
- 완료 기준: 발사와 재장전에서 탄약이 정확히 이전·차감되고, 장애물과 대상 명중이 구분됩니다.

### 4단계: 적 AI와 전리품

- 적의 순찰·감지·추적·공격·수색·사망을 구현합니다.
- 사망한 적에게서 전리품을 얻을 수 있도록 연결합니다.
- 완료 기준: 적과의 전투부터 사망 후 파밍까지 한 흐름으로 진행됩니다.

### 5단계: 레이드와 탈출

- 입장·타이머·탈출 구역·성공·사망·시간 초과·결과 화면을 구현합니다.
- 완료 기준: 모든 종료 사유가 한 번만 처리되고 결과 화면에서 다음 행동으로 이동할 수 있습니다.

### 6단계: 창고와 영구 저장

- 출격 장비 이전, 귀환 정산, 로컬 저장, 강제 종료·저장 실패·손상 대응을 구현합니다.
- 완료 기준: 재시작 후 상태가 복원되고, 보상 중복 지급과 아이템 이중 소유가 발생하지 않습니다.

### 7단계: 맵·연출·배포 마무리

- 맵 1개의 콘텐츠 배치, 사운드, UI, 성능과 실행 패키지를 완성합니다.
- 완료 기준: 개발 도구가 없는 대상 PC에서 처음 실행부터 반복 레이드까지 진행할 수 있습니다.

## 6. 최종 완료 판정

다음 항목을 실제 플레이와 재시작 시나리오로 확인해야 완성으로 판정합니다.

- [ ] 처음 실행한 사용자가 장비를 준비하고 레이드에 들어갈 수 있습니다.
- [ ] 이동·전투·아이템 사용·파밍을 거쳐 탈출할 수 있습니다.
- [ ] 사망·시간 초과·강제 종료가 정해진 실패 규칙으로 처리됩니다.
- [ ] 탈출과 실패 결과가 창고·장비·저장 데이터에 정확히 반영됩니다.
- [ ] 재시작하거나 결과 화면을 반복해도 아이템과 보상이 복제되지 않습니다.
- [ ] 장비를 모두 잃어도 다시 출격할 수 있습니다.
- [ ] 저장 실패·손상 시 잘못된 성공 안내나 조용한 데이터 덮어쓰기가 발생하지 않습니다.
- [ ] 개발 도구가 없는 PC에서 배포본이 실행되고 에셋·라이브러리가 정상 로드됩니다.
- [ ] 합의한 대상 환경에서 목표 성능을 충족하고 반복 플레이 중 자원 사용이 계속 증가하지 않습니다.

사용자의 빌드 금지 요청이 유지되는 동안에는 코드·경로·문서를 정적으로 점검합니다.
위 실행 관련 항목은 미검증으로 남기며, 빌드·실행이 허용된 뒤 검증합니다.

## 7. 이후 확장 범위

다음은 소규모 완성 버전 이후의 별도 작업입니다.

- 멀티플레이와 서버 권한·동기화
- 부위별 피해, 복잡한 출혈·치료 체계
- 총기 개조와 다수 무기·탄종
- 격자 인벤토리와 복잡한 장비 관리
- 상인, 퀘스트, 경제 시스템
- 추가 맵과 적 종류

우선 콘텐츠의 수를 늘리기보다 맵 1개·총기 1종·적 1종으로 전체 플레이 흐름을 완성합니다.
