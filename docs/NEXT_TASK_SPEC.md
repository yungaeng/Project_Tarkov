# 다음 작업 스펙: 아이템 사용·버리기

작성일: 2026-10-08
상태: 구현 제안. 이번 작업은 요구사항 정리이며 아래 기능과 수치는 아직 구현되지 않았습니다.

## 목표와 현재 상태

현재 구현된 줍기 → 보관 흐름에 선택 → 사용 또는 버리기 → 재줍기를 연결합니다.
현재 코드는 12슬롯, 종류별 묶음, 전체 수량 추가 또는 실패, 무게 표시를 지원합니다.
실제 빌드·실행과 ImGui 의존성 복원은 아직 검증하지 않았습니다.
사용자 지시에 따라 이번 문서 작업에서도 빌드·실행은 하지 않습니다.

## 구현 순서

1. 슬롯 선택과 안전한 수량 제거, 버리기·재줍기를 먼저 구현합니다.
2. 최소 플레이어 상태(체력·수분)를 추가한 후 아이템 사용을 연결합니다.
3. 상태 표시와 실패 안내를 완성하고 아래 완료 조건을 점검합니다.

체력·수분은 사용 결과를 표현하기 위한 최소 선행 기능입니다. 전투·출혈 시스템까지 확장하지 않습니다.

## 사용자 기능 요구사항

| 기능 | 요구사항 |
| --- | --- |
| 선택 | I로 연 인벤토리에서 행을 클릭하면 선택 강조와 상세 정보 표시 |
| 상세 정보 | 이름, 보유 수량, 묶음 한도, 개당·묶음 무게, 사용 효과 표시 |
| 사용 | Use 버튼 한 번에 선택 묶음의 1개만 사용. 즉시 효과 적용 |
| 버리기 | Drop 1, Drop All 버튼으로 1개 또는 선택 묶음 전체 버리기 |
| 재줍기 | 생성된 월드 아이템도 기존 F키·거리·가림·슬롯 조건 적용 |
| 안내 | 성공과 실패 원인을 화면에 표시. 실패 시 데이터 유지 |
| 입력 | 인벤토리와 창 포커스가 모두 활성일 때만 사용·버리기 허용 |
| 닫기 | I로 닫으면 선택을 해제하고 커서를 재포착. 다음 열기에서 자동 선택하지 않음 |

목록이 삭제·이동되어도 다른 아이템에 이전 선택이 잘못 적용되지 않아야 합니다.
선택된 묶음을 전부 제거하면 선택을 해제하고, 일부만 제거하면 같은 묶음을 계속 선택합니다.
UI는 현재 영어 기본 폰트를 유지하며 Use, Drop 1, Drop All로 표시합니다.

## 아이템 효과와 플레이어 상태: 제안 기본값

아래 수치는 최초 구현용 제안이며 게임 밸런스 확정값이 아닙니다.

| 항목 | 제안 스펙 |
| --- | --- |
| 체력 | 0~100, 정상 레이드 시작값 100 |
| 수분 | 0~100, 정상 레이드 시작값 100 |
| 붕대 | 체력 +20, 성공 시 1개 소비. 출혈 없는 초기 버전의 임시 회복 효과 |
| 물 | 수분 +30, 성공 시 1개 소비 |
| 탄약 | 보관·버리기만 가능. 무기·재장전 구현 전에는 Use 비활성 |
| 최대치 | 이미 최대치면 사용 거부·미소비. 회복량 일부라도 적용되면 1개 소비하고 100에서 제한 |
| 상태 변화 | 시간 경과에 따른 수분 감소, 피해, 사망, 스태미나는 이번 범위에서 제외 |

체력과 수분은 Player가 소유하는 PlayerVitals에 둡니다.
HUD와 인벤토리에서 현재값과 최대값을 표시합니다.
회복 검증을 위해 테스트에서만 체력·수분을 낮게 지정할 수 있어야 하며 정상 시작값은 변경하지 않습니다.

## 버리기 위치 규칙

- 캐릭터 발 위치와 카메라의 수평 전방 방향을 기준으로 배치 후보를 계산합니다.
- 후보는 전방 1.0m, 전방 좌우 45도 방향 각 1.0m 순서로 확인합니다.
- 공중에서는 버리기를 거부합니다. 유효한 지면이 없으면 아이템을 공중에 생성하지 않습니다.
- 후보 지점 위 0.5m부터 아래로 2.0m 범위에서 가장 가까운 정적 상자 윗면을 찾습니다.
- 아이템 바닥은 지면 윗면에 놓고 현재 상자 반크기 0.2를 사용합니다.
- 바닥을 제외한 정적 장애물, 캐릭터 몸체, 기존 월드 아이템과 부피가 겹치면 해당 후보를 거부합니다.
- 캐릭터 쪽에서 후보까지 아이템 크기를 고려한 이동 공간을 검사하여 얇은 벽 너머 배치를 차단합니다.
- 배치 가능한 후보가 없으면 버리기를 실패 처리하고 인벤토리를 그대로 유지합니다.
- 기존 아이템과 합치거나 물리적으로 튕겨내는 처리는 이번 범위에서 제외합니다.

## 데이터 무결성과 처리 순서

아이템 사용과 버리기는 성공 시에만 수량을 차감하며 실패 시 상태·수량 모두 그대로여야 합니다.
아이템 수량은 항상 양수, 슬롯 수는 12 이하, 묶음 수량은 종류별 최대치 이하여야 합니다.

- UI는 데이터 변경 대신 요청(대상 묶음 ID, 동작)을 생성합니다.
- Update 단계에서 최신 상태·수량·포커스를 다시 검증한 후 요청을 한 번만 처리합니다.
- 벡터 인덱스나 요소 포인터를 프레임 사이 선택값으로 보관하지 않고 안정적인 묶음 ID를 사용합니다.
- 버리기는 위치와 월드 저장 공간을 먼저 준비한 뒤 인벤토리 차감과 월드 생성을 함께 확정합니다.
- 사용은 효과 적용 가능 여부를 확인한 뒤 회복과 1개 차감을 함께 확정합니다.
- 인벤토리 닫기, 포커스 상실, 장면 종료 시 대기 중 요청을 취소합니다.
- 월드 아이템 생성·삭제 후에는 기존 조준 대상 인덱스를 무효화하여 다음 Update에서 다시 계산합니다.
- 연속 클릭으로 수량이 음수가 되거나 동일 요청이 두 번 실행되지 않아야 합니다.

Inventory는 위치나 OpenGL을 알지 않으며 RaidHud는 인벤토리와 월드를 직접 변경하지 않습니다.
기존 glfw/OpenGL3 ImGui 바인딩으로 구현하며 추가 외부 라이브러리는 필요하지 않습니다.

## 완료 조건

| 시나리오 | 기대 결과 |
| --- | --- |
| 붕대 2개, 체력 50에서 Use | 체력 70, 붕대 1개 |
| 체력 95에서 붕대 사용 | 체력 100, 1개 소비 |
| 체력 100에서 붕대 사용 | 미소비, 사용할 수 없는 이유 표시 |
| 수분 80에서 물 사용 | 수분 100, 물 1개 소비 |
| 탄약 선택 | Use 비활성, 버리기 가능 |
| 탄약 60개에서 Drop 1 | 인벤토리 59, 월드에 1 생성 |
| 선택 묶음 Drop All | 해당 묶음만 제거, 같은 수량 월드 생성, 선택 해제 |
| 버린 아이템 재줍기 | 종류별 총수량 보존, 기존 묶음 규칙 유지 |
| 벽 앞·지면 없음·공중·모든 후보 겹침 | 생성과 차감 모두 없음 |
| 마지막 묶음 사용·버리기 | 빈 인벤토리 안내, 잘못된 선택 접근 없음 |
| 클릭 직후 닫기·포커스 상실·장면 종료 | 대기 요청 취소, 소비·생성 없음 |
| 연속 클릭·가득 찬 인벤토리 | 중복 처리·아이템 복제·소실 없음 |

검증은 순수 데이터(묶음 제거, 회복, 실패 시 불변, 총수량 보존)와 배치 판정 경계 사례를 우선합니다.
빌드 금지 요청이 유지되는 동안에는 코드·경로 검토만 수행하고 실행 통과로 기록하지 않습니다.
향후 빌드·실행이 허용되면 먼저 기존 줍기와 ImGui 화면부터 확인한 뒤 신규 기능을 검증합니다.

## 이후 단계

영구 저장, 창고, 장비 슬롯, 격자 인벤토리, 드래그 이동, 아이템 사용 애니메이션,
