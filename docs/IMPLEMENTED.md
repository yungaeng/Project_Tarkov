## 1. 현재 게임 범위

로컬 싱글플레이 산업단지 레이드 프로토타입이다. 은신처에서 장비를 준비하고 출격한 뒤 탐색·루팅·AI 전투·탈출 또는 사망/MIA를 거쳐 은신처로 돌아오는 흐름이 연결되어 있다.

## 2. 빌드와 실행

### 2.1 개발 환경

- Windows, Visual Studio 2022의 C++ 데스크톱 개발 도구, MSVC v143, Windows SDK가 필요하다. 기본 확인 구성은 Debug | x64이며 Release | x64도 제공한다. Win32는 검증 대상으로 간주하지 않는다.
- 루트 `vcpkg.json`이 GLAD 1/OpenGL 3.3 loader, GLM, Assimp, stb, GLFW3, ImGui의 GLFW/OpenGL3 바인딩을 선언한다. baseline이 고정되어 있다.
- `VCPKG_ROOT`로 vcpkg 설치 위치를 지정한다. 기본 경로는 `%USERPROFILE%\vcpkg`이며 부트스트랩된 `vcpkg.exe`가 필요하다. 최초 복원에는 네트워크가 필요하다.
- 저장소 루트의 `Project_Tarkov.sln`을 열고 **Debug | x64**로 빌드한다. NuGet 복원이나 별도 `glad.c` 추가는 필요하지 않다. `Project_Tarkov/src/Graphics/Texture.cpp`가 stb_image 구현을 제공한다.
- `.build`와 `vcpkg_installed`는 생성물/의존성 영역이다. 저장소 소스와 구분한다. Visual Studio 프로젝트 출력 및 중간 파일은 `Project_Tarkov/x64/Debug/` 아래에 둔다.

### 2.2 실행 자원과 배포

`CopyRuntimeAssets` 빌드 타깃이 실행에 필요한 셰이더·애니메이션·맵 데이터·UI 이미지·모델을 `Project_Tarkov/x64/Debug/Assets/`에 복사한다. 개발 빌드에서는 실행 파일 상위의 저장소 루트 `Assets/`를 사용하고, 패키지 실행에서는 실행 파일 옆 `Assets/`를 사용한다. 경로 탐색은 현재 작업 디렉터리를 바꾸지 않는다. Visual Studio 디버깅 작업 디렉터리는 실행 출력 폴더다.

```powershell
.\Project_Tarkov\x64\Debug\Project_Tarkov.exe
```

필수 자원은 `Assets/Shaders/`, `Assets/Animations/`, `Assets/Maps/`, `Assets/Models/`, `Assets/UI/` 아래에 둔다. 예전 안내처럼 원본 FBX 하나만 복사해서는 현재 캐릭터가 구성되지 않는다. 배포 시 EXE·필요 DLL·복사 대상 `Assets/`를 함께 제공해야 한다.

저장 위치는 현재 작업 디렉터리와 무관하게 결정한다. `TARKOV_SAVE_ROOT` 절대 경로가 최우선이며, 미지정 시 실행 파일 옆 `Saves/hideout.txt`가 있으면 그 프로필을 사용한다. 실행 파일 옆 프로필이 없을 때에만 저장소 루트 및 예전 프로젝트 경로의 프로필을 탐색한다. 과거 후보가 하나면 제자리에서 사용하고, 둘 이상이면 명시적인 `TARKOV_SAVE_ROOT` 설정을 요구한다. 기존 후보가 없으면 실행 파일 옆에 새 프로필을 생성한다. 자동 이동·병합은 없으며, 정상 플레이 중에는 선택된 프로필을 기존 저장 방식으로 갱신한다. `TARKOV_ASSET_ROOT`는 에셋 루트만 별도로 지정한다.

### 2.3 알려진 환경 문제

GLAD 헤더/심볼 오류는 vcpkg 복원과 GLAD 1 API 구성을 확인한다. 에셋 로딩 실패는 Assets 복사 대상, 저장소 루트 탐색 및 TARKOV_ASSET_ROOT 설정을 확인한다. 과거 MSBuild의 PATH/Path 중복 문제 및 MSPDB140.DLL 문제가 기록되어 있다. 2026-10-20 검증에서는 로컬 `.build/qa/no-link-pdb.targets`로 링크 PDB 생성만 우회했으며, 기본 프로젝트 디버그 설정을 변경했다는 뜻은 아니다.

RaidScene이 플레이어·충돌 월드·표현 자원을 소유하고 Character는 충돌 월드를 비소유 포인터로 참조한다. `EntityManager`에는 `unique_ptr` 기반 소유 API가 있지만 현재 주요 실행 경로의 필수 관리자는 아니다. Mesh/Shader/Texture는 복사를 막고 자원 수명을 관리한다. 장면·GPU 자원과 ImGui를 먼저 해제한 뒤 입력과 OpenGL 창을 종료한다.

## 4. 조작·이동·물리·카메라

### 4.1 현재 키 배치

| 입력 | 동작/제약 |
| --- | --- |
| WASD / 마우스 | 카메라 수평 방향 기준 이동 / 시점 회전 |
| 왼쪽 Shift / 왼쪽 Ctrl | 달리기 / 누르는 동안 웅크리기 |
| Space / Z | 지상 점프 / 엎드리기 전환 |
| I | 인벤토리 전환과 커서 해제/포착 |
| F | 가까운 시체 파밍 창 열기, 조준한 아이템 줍기, 구조 대상 대화, 은신처 가구 이용 및 창고 UI 닫기 |
| V / 왼쪽·오른쪽 Alt | 1·3인칭 전환 / 누르는 동안 자유 시점 |
| 1 / 2 / 3 | 주무기 1 / 주무기 2 / 부무기 선택·해제 |
| B | 단발 → 연발 → 안전 전환 |
| 마우스 왼쪽 / 오른쪽 | 클릭당 단발 / 누르는 동안 조준 |
| R | 재장전 시도; 1초 이상 유지하면 잔탄 표시 |
| F / I / Esc | 시체 파밍 창 닫기 |
| Esc (은신처) | 반투명 일시 정지 메뉴 열기/닫기 |
| T | 배정된 탈출구로 즉시 이동하는 개발 편의 기능 |
| F11 / Q | 전체 화면 전환 / 애플리케이션 종료 |

이 배치는 원작의 키 배치가 아니다. 특히 Q는 기울이기가 아니라 종료다. T 이동은 현재 코드에 일반 입력으로 연결되어 있으며 정식 플레이의 이동 규칙으로 보지 않는다. 예전 2/3 스폰 선택 안내는 현재 진입 경로와 맞지 않는다.

### 4.2 이동 수치와 자세

| 값 | 현재 설정 |
| --- | --- |
| 걷기 / 달리기 / 웅크리기 / 포복 | 3 / 6 / 2.5 / 0.8m/s |
| 몸체 반너비 | 0.35m |
| 서기 / 웅크리기 / 엎드리기 높이 | 1.8 / 1.1 / 0.55m |
| 기본 눈높이 | 1.7 / 1.0 / 0.45m |
| 중력 / 최대 낙하 속도 | 9.81m/s² / 50m/s |
| 점프 초기 수직 속도 | 5m/s |
| 추적 카메라 거리 / 높이 보정 | 2.4 / 0.05m |
| 마우스 감도 / 피치 제한 | 0.1 / ±89도 |

근거: `Game/Character/CharacterSettings.h`, `Game/Config/RaidConfig.h`, `Game/Character/Character.cpp`.

이동 벡터는 수평 정규화하여 대각선 입력으로 속도가 늘어나지 않게 한다. 매 프레임 이전 이동/달리기 명령을 지운 뒤 새 입력을 적용한다. 실제 이동량으로 이동 여부와 애니메이션 속도를 계산한다. 벽에 막혀 이동하지 않으면 걷기 애니메이션을 계속 재생하지 않는다.

점프는 활성·지상·지지면 조건을 검사하며 웅크림/엎드림/수색 중에는 불가능하다. 공중 연속 점프도 차단한다. 엎드리기는 지상에서 진입하고 서기 전 전체 몸체가 들어갈 공간을 확인한다. 낮은 천장 아래에서는 Ctrl을 놓아도 일어서지 않는다. 자세 변경 시 발 기준 위치를 유지한다.

### 4.3 충돌과 시간

CollisionWorld는 정적 축 정렬 상자를 보관한다. Character는 최대 1/120초의 소단계로 X→Z→Y 이동을 검사하여 벽 정지·벽 따라 이동·중력·착지를 처리한다. 초기 겹침은 제한된 반복으로 해소한다. Character 자체는 한 번에 최대 1초를 처리하지만 현재 RaidScene은 물리·AI·상태용 dt를 0.1초로 제한한다.

반면 레이드 제한 시간과 탈출 대기는 제한 전 경과 시간을 사용한다. 따라서 창 비활성화나 긴 프레임에도 레이드 시계는 흐르며, 생존 수치와 AI가 동일한 실시간을 모두 시뮬레이션하는 것은 아니다.

CombatSystem에는 살아 있는 캐릭터 및 시체와의 보수적 수평 분리 처리가 추가되어 있다. 완전한 동적 강체/정밀 시체 충돌은 아니며 정적 지형이 우선한다. 경사면, 자동 계단 오르기, 메시 충돌, 래그돌은 구현 범위 밖이다. 기본 산업단지 지면은 Y=0이며 과거 테스트 바닥 Y=-0.9 안내는 현재 맵 기준이 아니다.

### 4.4 카메라와 입력 안정성

1인칭은 애니메이션의 머리 위치와 머리·목·상체·어깨 근처 여유 영역으로 카메라를 보정한다. `cube.fs`에는 카메라 가까운 상단 신체 조각을 버리는 처리도 존재한다. 따라서 과거의 “머리를 포함한 메시를 전혀 숨기지 않음” 설명은 현재 코드와 다르다.

3인칭은 바닥 아래로 내려가지 않도록 Y≥0.25를 적용한다. **월드 벽과 카메라 사이의 스윕 충돌은 아직 없다.** Alt 자유 시점은 별도 카메라를 사용하고 이동/조준 기준 카메라를 유지한다. 시체 수색 중에는 전용 측면 카메라와 별도 UI 공간을 사용한다.

입력은 포커스를 잃으면 차단하고, 포커스 세대 변화 시 아이템 요청과 재장전을 취소한다. 커서 재포착 및 전체 화면 전환 시 마우스 이동량을 초기화한다. 최소화로 프레임버퍼 크기가 0이면 레이드 렌더링을 건너뛴다. 인벤토리/수색은 게임 전체 일시정지가 아니다.

## 5. 플레이어 상태와 치료

`PlayerVitals.h`는 머리·몸통·골반·양팔·양다리 7부위를 각각 100으로 시작한다. 합계는 700이지만 `Health()` 반환값은 7부위의 **평균**이다.

| 규칙 | 현재 동작 |
| --- | --- |
| 사망 | 머리+몸통 ≤50 또는 모든 부위가 각각 ≤50 |
| 단일 부위 피해 | 지정 부위만 감소, 최저 0 |
| 전체 피해 | 각 부위에 같은 피해를 적용 |
| 붕대 | 선택 부위 +20, 상한 100, 한 개 소비 |
| 물 | 수분 +30, 상한 100, 한 개 소비 |
| 수분 감소 | 시뮬레이션 초당 0.1 |
| 탈수 | 수분 0에서 모든 부위에 초당 0.5 피해 |
| 달리기 | 실제로 달려 이동할 때 스태미나 초당 22 소비 |
| 회복 | 그 외 스태미나 초당 14 회복 |
| 완전 소진 | 스태미나 20 이상 회복 전까지 달리기 재개 금지 |
| 맵 밖 낙하 | Y<-30에서 모든 부위에 100 피해 |

레이드 치료는 붕대 우클릭 메뉴에서 치료 부위를 선택한다. 은신처 캐릭터 패널 아래 실루엣을 클릭하거나 붕대 우클릭으로 치료한다. 필요 없는 치료/물 사용은 소비하지 않는다. 부위 상태는 손상 시 표시하고 체력 10 이하를 검정, 50 이하를 빨강으로 구분한다. 수분·스태미나 경고는 각각 10 이하에서 표시한다. 좌하단에는 서기/앉기/엎드림 실루엣과 그 아래 스태미나·수분 막대를 항상 표시한다. 피격 실루엣은 목·어깨·허리·팔다리 윤곽을 가진 다각형으로 바꾸고 부위별 체력 색을 유지했다.

체력·수분·스태미나는 귀환 후 프로필에 유지된다. 현재 사망 판정을 만족하면 은신처에서 치료하기 전 출격을 차단한다. 별도 에너지/허기, 출혈·골절·진통·수술, 부위별 최대 체력 차이, 방탄 피해 계산은 없다. 붕대의 직접 체력 회복은 프로젝트의 간소화 규칙이다.

## 6. 아이템·장비·인벤토리

### 6.1 현재 아이템 정의

기존 ID 0~10은 유지한다. 붕대(5개/칸, 0.1kg), 물(2개/칸, 0.6kg), 공용 탄약(**30발/칸**, 0.01kg/발), 상의·하의·속옷 2종·조끼·헬멧·배낭·군화는 기존 무게와 착용 슬롯을 사용한다.

새 ID는 11 소총(3.5kg), 12 소총 탄창(0.25kg, 30발), 13 권총(0.9kg), 14 권총 탄창(0.12kg, 15발)이다. 총기와 탄창은 각각 1개/칸이며 개별 잔탄량을 가진다. 삽입된 탄창의 유무와 총기의 사격 모드도 저장한다. 소총/권총 탄창은 서로 호환되지 않는다. 낱탄은 현재 공용 탄약으로 간소화했다.

휴대품은 고정 슬롯을 쓴다. 주머니 0~11, 조끼 12~17, 배낭 18~29이며 해당 장비가 없으면 슬롯을 사용할 수 없다. 주무기 1/2는 -1/-2, 부무기는 -3으로 별도 관리한다. 총기는 빈 무기 슬롯에 우선 장착하고, 없으면 휴대품에 넣는다. 무기 슬롯과 주머니/배낭 사이를 드래그할 수 있다. 무게에는 총기·삽입 탄창·탄창 내부 탄약이 포함되지만 착용 의류까지 포함한 이동 제한 시스템은 아직 없다.

### 6.2 UI·이동·장착

은신처와 레이드 모두 **캐릭터 장비 슬롯 / 주머니·조끼·배낭 / 창고 또는 바닥·적 장비**의 3열 UI를 사용한다. 각 패널은 스크롤할 수 있다. 슬롯에는 Assets/UI/items.png의 사진형 아이템 이미지를 표시하고 수량 또는 잔탄을 겹쳐 그린다. 티팬티 이미지는 2026-11-03 사용자가 첨부한 검정 가는 끈 형태를 반영했다. 캐릭터 착용 메시 자체는 이번 이미지 작업으로 교체하지 않았다.

- 빈 칸으로 드래그하면 위치를 바꾼다. 같은 컨테이너의 점유 칸은 슬롯 종류가 허용하면 교환하며, 동일 소비품은 최대 스택까지 합친다.
- 의류는 해당 착용 칸으로 드래그하거나 우클릭으로 착용한다. 은신처 의류 가구에 보관된 방탄복·배낭도 바로 착용할 수 있다. 착용 의류는 휴대품/창고로 드래그해 해제한다. 조끼·배낭 안에 물건이 남으면 해당 장비를 벗을 수 없다.
- 물은 우클릭 사용, 붕대는 우클릭 치료 부위 선택을 지원한다. 필요 없는 회복은 소모하지 않는다.
- 창고와 휴대품 간 이동은 잔탄·삽입 탄창·사격 모드를 보존한다. 실패한 이동은 원본을 남긴다.
- 요청은 UI를 모두 그린 뒤 적용하므로 순회 도중 컨테이너가 바뀌지 않는다. 바닥 버리기는 다음 Update에서 지면/가림 검사를 거친다.

드래그는 벡터 순서와 분리된 StackId를 사용한다. 새 컨테이너 진입과 저장 재읽기 때 ID를 다시 부여하며, 같은 컨테이너 내 위치 이동은 ID를 유지한다.

### 6.3 월드 줍기·버리기

월드 아이템은 `LootSystem`이 소유하고 색상 상자로 표현한다. 카메라 중심 광선과 플레이어 눈 기준 거리 2.5m, 카메라/플레이어 양쪽의 장애물 가림을 검사한다. 획득 가능 대상은 강조하고 F의 눌림 이벤트에서 한 번만 처리한다. 인벤토리 수용 성공 후에만 월드에서 제거한다. 바닥 패널에는 눈 위치 기준 2.5m 안이며 벽으로 가려지지 않은 물품을 표시하고, 드래그 획득 때 접근 조건을 다시 검사한다. 총기/탄창의 잔탄과 상태도 보존한다.

UI의 바닥 드롭과 우클릭 이동은 전체 스택을 버린다. 내부 API는 1개 버리기도 유지한다. 전방 1m와 좌우 45도 후보를 검사하고, 발 주변 높이에서 아래쪽 지면·전체 지지·장애물·자기 몸체·기존 아이템 겹침·벽 통과를 확인한다. 유효 위치가 없거나 공중이면 아이템을 유지한다. 월드 저장 공간 확보 후 수량 제거와 생성이 이루어진다. 지면 위에는 작은 오차 여유를 둔다.

## 7. 소총과 전투

총기와 탄창은 Inventory의 개별 ItemStack으로 저장한다. 1/2/3키로 주무기 1/2 및 부무기를 선택한다. B키는 단발 → 연발 → 안전 → 단발 순서로 전환한다. 단발은 클릭 이벤트당 1발, 연발은 누르는 동안 0.15초 간격, 안전은 탄약 차감·총성·명중 판정을 모두 차단한다.

| 값 | 현재 동작 |
| --- | --- |
| 탄창 | 소총 30발 / 권총 15발, 약실 별도 상태 없음 |
| 사격 | B로 단발/연발/안전, 최소 간격 0.15초 |
| 적에게 주는 피해 | 명중당 34, 적 체력 100 |
| 조준 광선 | 카메라 기준 최대 100m에서 목표점 탐색 |
| 재장전 | 2초 후 조끼에서 호환 탄창 교체, 최다 잔탄 우선 |
| FOV | 기본 75도 / 조준 50도 |
| 카메라 반동 | 비조준 1.6도 / 조준 0.7도 피치 증가 |

카메라 광선으로 목표를 정하고 플레이어 눈에서 목표까지 다시 검사한다. 이 두 단계 판정으로 3인칭 카메라만 엄폐 밖에 나온 상태의 사격을 제한한다. 정적 벽과 가장 가까운 살아 있는 적 AABB를 비교한다. 적은 34 피해 세 번으로 사망하며 실제 머리 맞음에 따른 배율은 없다. 결과 기록의 머리/몸통 표기는 충돌 높이로 분류한 통계일 뿐 피해 모델과는 다르다.

발사 시 탄약 차감, 총성, 총구 화염/노리쇠/총기 반동, 명중·빗나감·엄폐·빈 탄창 메시지가 연결되어 있다. 재장전은 인벤토리 열기, 포커스 상실, 무기 해제, 사망 등에 취소되고 완료 전에 탄창을 교체하지 않는다. R은 누르기 시작할 때 재장전을 시도하므로 길게 누르는 잔탄 확인과 완전히 분리된 입력이 아니다. 잔탄 표시 유지 시간은 3초다.

탄약을 탄창 위에 드롭하거나 탄창 우클릭 메뉴의 **1발만 채우기 / 전부 채우기 / 전부 빼내기**를 사용한다. 메뉴는 같은 컨테이너의 탄약을 쓰고, 다른 컨테이너 탄약도 직접 드래그할 수 있다. 탄약을 빼낼 공간이 없으면 전체 작업을 취소한다. 탄창을 총기에 드래그하면 삽입하며, 기존 탄창은 공급 탄창의 원래 칸으로 돌아간다. 총기 우클릭의 탄창 분리는 빈 휴대/창고 칸이 필요하다.

R은 **착용한 조끼의 12~17번 칸**에서 호환 탄창만 선택한다. 잔탄이 가장 많은 탄창을 고르고, 모두 비어 있어도 0발 탄창을 장착한다. 주머니·배낭 탄창과 낱탄만으로는 재장전할 수 없다. 기존 탄창은 선택한 탄창 칸에 보관하므로 휴대품이 가득 차도 교환한다. 탄창 없는 총기에 삽입하면 공급 탄창 칸이 비워진다. 완료 때 무기 ID·탄창 ID·조끼 위치를 다시 확인한다.

실제 탄환 이동·낙차·관통·도탄·탄종 차이·약실·고장·내구도·부착물 성능은 아직 없다. 권총은 별도 아이템/슬롯/15발 탄창과 사격 규칙을 가지지만 3D 무기 모델·손 포즈·효과음은 기존 소총 표현을 공유한다.

## 8. 적 AI와 시체 수색

### 8.1 적 생성과 판단

`IndustrialZone::Enemies`의 5개 좌표로 생성한다. 각 적은 독립 Character, 체력 100, 소총 소유 상태, 인벤토리, 시각 포즈를 갖는다. 탄약 20·붕대 1·물 1·20발 소총 탄창 1개를 초기 소지하고 사망 시 착용 의류를 전리품 인벤토리에 넣는다.

| 상태 | 현재 규칙 |
| --- | --- |
| Patrol | 원래 위치와 X+4m 사이 순찰, 속도 1.4m/s |
| Chase | 18m 미만·장애물 가림 없음으로 발견, 마지막 관측 위치 갱신, 속도 2.8m/s |
| Attack | 발견된 대상이 11m 미만이면 공격, 재공격 간격 1.2초 |
| Search | 시야 상실 후 마지막 관측 위치를 5초 수색 |
| Dead | 공격 중지, 중력/사망 모션, 수색 가능한 시체 유지 |

감지는 거리+가림 검사이며 방향별 시야각/청각 감지는 없다. 적 공격은 플레이어의 한 부위에 40 피해를 직접 적용한다. 부위는 적 인덱스와 경과 시간으로 선택하며 탄도 피격점 계산이 아니다. 적의 사격 탄약 소모/재장전/명중률 모델도 없다.

장애물 앞에서는 0.8m 전방과 좌우 후보를 확인한다. NavMesh나 전역 경로 탐색이 아니므로 복잡한 실내와 가구 주변 이동 품질은 별도 검증이 필요하다. 사망/시야 상실과 무관하게 발포하는 AI로 설명해서는 안 되지만, 원작과 같은 탐지/전술 AI로 평가해서도 안 된다.

### 8.2 시체 접근과 수색

사망 후 1.25초 이상 경과하고 지면에 닿은 시체가 대상이다. 시체 중심 2.5m 이내, 벽 가림 없음, 엎드리지 않은 상태에서 F를 누르면 시체 뒤 기본 무릎 파밍 자세를 취하며 파밍 UI를 바로 연다. 별도의 자세 진입 단계는 없고, F/I/Esc, 종료 버튼, 포커스 상실로 UI를 닫으면 접근 전 위치·방향·카메라로 돌아간다. 자세는 지지점·정적 공간·주변 캐릭터/시체 공간을 검사하는 `FitLootPose` 경로로 맞춘다.

수색 UI도 동일한 3열 인벤토리를 쓰며 오른쪽에 적 무기와 휴대품을 표시한다. 드래그 또는 우클릭 이동으로 획득하고, 소총 획득 버튼은 빈 주무기 슬롯 → 휴대품 순으로 수용한다. 공간이 없으면 원본이 남는다. 재개방해도 가져간 물품을 재생성하지 않는다. 의류와 소총을 가져가면 시체 외형에 반영한다. 시체 소총은 30발 탄창을 포함한 아이템으로 회수하며 AI의 실제 사격량에서 잔탄을 계산하는 시스템은 아직 아니다.

파밍 UI가 열려 있는 동안 이동·사격을 막으며 AI·상태·타이머는 계속 진행하고 무적은 없다. UI를 닫으면 플레이어 조작을 복구한다. 과거 “적 사망 시 바닥에 탄약 20 자동 생성”은 현재의 시체 인벤토리 방식으로 대체되었다.

`IndustrialDetails.h`는 기둥·보·출입구 프레임·지붕 환기 장치, 컨테이너 요철/문/잠금봉, 저장 탱크·굴뚝·폐차·모래주머니를 추가한다. 식생은 줄기·침엽수/활엽수 수관·덤불·바위이고, 비포장 오솔길 7개·잔디 밀집 구역 3곳·텐트 야영지 7곳·화로드럼통이 있다.

나무 줄기·바위·가구·설비·폐차·텐트 등 주요 구조물은 단순 상자 충돌을 사용한다. 오솔길·작은 장식·수관·덤불은 비충돌 시각 요소다. 특히 덤불은 시야나 총알을 막는 엄폐물이 아니다. 화염 표현이 있어도 주변을 밝히는 동적 광원은 아니다. 실제 고저차/배수로는 후속 범위다.

### 9.3 루팅

건물마다 고정 위치 4곳, 총 20곳에 아이템을 생성한다. 15종 중 무작위로 뽑고 탄약은 30발, 나머지는 1개다. 위치와 구역별 희귀도는 무작위가 아니며 고급 공장/의료 관리동 같은 특화 드롭 테이블은 없다. 검색 시간이 필요한 컨테이너도 아직 없다.

| 스폰 | 배정 탈출구 |
| --- | --- |
| 남서 (-210,0,210) | X1 북동 검문소 (225,0,-220) |
| 북서 (-210,0,-210) | X2 남동 폐도로 (225,0,220) |

제한 시간은 1,500초다. 배정 탈출구의 X/Z 각각 ±6m인 사각형과 높이 차 2m 미만 조건에서 8초 머무르면 성공한다. 이름이 `ExtractRadius`여도 원형 거리 판정이 아니다. 구역 이탈 또는 수색 중이면 카운트가 초기화된다. 피격 자체는 취소하지 않지만 사망하면 실패하며, 같은 프레임 시간 만료는 탈출보다 우선한다. 모든 적을 처치해도 자동 종료하지 않는다.

### 10.2 상태별 정산

| 결과 | 처리 |

사망/MIA와 성공의 결과 UI 경로는 서로 다르다. 재출격 시 AI·루팅·타이머·카메라·요청/시각 상태를 초기화한다.

## 11. 은신처·창고·저장

### 11.1 장비 준비 UI

은신처 UI는 장비·건강 탭, 캐릭터 주변 장비 카드, 캐릭터 회전, 조끼·주머니·특수 슬롯·배낭 배치, 검색/자동정리 및 화면 폭에 따른 패널 구성을 사용한다. 화면은 반투명하며 뒤에 은신처 맵과 캐릭터가 계속 렌더링된다. UI에서 F를 누르면 맵으로 돌아가고 Esc는 계속하기/게임 종료 메뉴를 표시한다. UI 상단의 동작 버튼은 제거했으며 물 마시기는 장비 화면의 수분 표시 옆에서 할 수 있다. 건강 탭은 피격 실루엣과 캐릭터 미리보기, 창고를 표시하며 부위 클릭 또는 붕대 드래그로 치료한다. 물 마시기는 냉장고 물을 먼저 쓰고 없으면 기존 창고와 휴대 물을 차례로 사용한다. 수분 +30과 물 1개 소비를 함께 저장하며, 수분이 가득 차면 소모하지 않고 저장 실패 시 변경을 되돌린다.

새 프로필은 소총 1자루(삽입 탄창 30발), 조끼에 30발 탄창 1개와 빈 탄창 1개, 배낭을 제외한 기본 착용 장비, 창고 붕대 10·배낭 1 및 냉장고 물 3개로 시작한다. 기존 프로필 이관 때 창고에 있던 물은 냉장고로 옮기며 새 보급품을 중복 지급하지 않는다.

### 11.2 창고

기본 10열×8행, 80칸 격자다. 2026-11-04부터 아이템의 원래 가로·세로 점유 크기를 복구했다. 다중 칸 아이템은 전체 영역이 비어 있어야 배치할 수 있다. 검색과 자동 정리를 유지하며 자동 정리는 큰 면적부터 배치하고, 전부 배치하지 못하면 원래 배치를 유지한다. 아이템 툴팁은 개당 가격과 묶음 가격을 보여준다. 창고 아이템 우클릭 메뉴에서 판매하면 수량만큼 루블이 잔액에 추가되고, 분할은 묶음을 절반으로 나눠 빈 슬롯에 놓는다. 드래그로 같은 종류의 묶음에 겹치면 최대 묶음 수량까지 합쳐진다. 창고 오른쪽 상단에는 보유 루블을 표시한다. 회전은 아직 지원하지 않는다.

일반 창고에는 전체·무기·탄약/탄창·의류·의료품·음식/물 카테고리 탭을 제공해 항목별로 필터링한다. 가구 보관함도 은신처와 동일한 캐릭터/장비·휴대품·보관품 3열 UI를 사용하고, 해당 가구가 허용하는 아이템만 우측 보관품 격자에 표시한다.

기존 v1~v9 초과 재고는 필요한 만큼 확장된 슬롯으로 보존한다. 옛 60발 탄약 묶음은 30발씩 나누며, 휴대품에 들어가지 못한 묶음은 창고로 옮긴다. 새 이동은 전체 수용이 가능할 때만 반영한다.

### 11.3 저장 형식과 실패 대응

Saves/hideout.txt의 헤더는 HIDEOUT 19이다. 착용 마스크·루블 잔액·구조 인원 수와 방별 점유 마스크, 일반 창고·휴대품·4개 방별 가구 보관함의 용량과 항목 수, 각 항목의 종류·수량·고정 슬롯·잔탄·탄창 삽입 여부·사격 모드, 7부위 체력·수분·스태미나, END를 기록한다. 기존 v1~v18을 읽어 변환하며 v18 이전 저장 파일의 루블 잔액과 구조 인원은 0으로 시작한다. 이전 창고 물은 냉장고 공간이 허용하는 만큼 이관하고 나머지는 기존 창고에 보존한다. 예전 소총 boolean/잔탄은 주무기 1 슬롯의 총기 아이템으로 옮기며, v17 미만 프로필을 변환할 때만 기본 보관품을 추가한다.

읽을 때 버전·종류·수량·용량·착용 마스크·유한한 상태값 범위·종료 마커와 여분 토큰을 검사한다. 손상되면 원본을 덮어쓰지 않고 프로필을 비활성화한다. 저장은 임시 파일 기록/flush/close 뒤 `MoveFileExW`의 교체와 write-through로 반영한다.

장비 이동/장전/치료/정리 등 저장 실패 시 이전 상태로 되돌리는 경로가 있다. 출격용 저장 실패는 출격을 막는다. 탈출 회수 저장 실패는 회수품을 메모리에 유지하고 재시도해야 한다. 현재 성공 결과 장면이 저장 실패 상태까지 충분히 보여주는지는 후속 검증 항목이다. 원자적 파일 교체가 정전·손상·정산 재진입의 모든 경우를 검증했다는 뜻은 아니다.

## 12. 캐릭터·애니메이션·제작 도구

### 12.1 현재 외형과 데이터

플레이어와 적은 여캐 외형을 공유하고 적은 갈색 계열 색으로 구분한다. `Ch22_nonPBR.fbx`는 애니메이션 리그 기반이며 `LoadAppearance`가 `여캐/character.mesh` 외형과 바인드 정보를 적용한다. 원본 PMX의 과거 외부 드라이브 경로는 개발자 로컬 자료로서 저장소만으로 복원되는 입력이 아니다.

전술 상의·하의·조끼·헬멧·군화, 속옷과 별도 배낭 표현이 연결되어 있다. 기존 전술복/속옷/군화의 개별 편집용 `.mesh`는 ArtSource 정리 때 삭제했으며 실제 표시에는 Assets의 통합 `character.mesh`가 사용된다. 몸과 의류는 동일 본 팔레트를 사용한다. 조끼는 몸통 중심 가중치로 구성하며 배낭은 절차적으로 만든 외피/디테일을 표시한다. 겉옷에 가려지는 피부와 속옷은 셰이더의 garment/착용 비트 규칙으로 처리한다.

현재 로더는 `TKCHAR01`~`TKCHAR05`를 받아들인다. 최신 형식은 군화 garment 8을 포함한다. 바이너리는 little endian이며 magic, 관절/정점/인덱스 수, 이름과 바인드 위치, 정점 위치·법선·UV·관절/가중치·garment, 삼각형 인덱스로 구성된다. 위치 단위는 모델 센티미터이며 월드 배율은 0.01이다. import 도구는 PMX 좌표계와 삼각형 방향을 변환한다.

과거 문서의 31,550 정점/48,842 삼각형은 몸/머리만 임포트한 시점의 수치다. 전술복·군화가 합쳐진 현재 전체 메시의 확정 통계로 사용하지 않는다. PMX 얼굴 모프와 머리카락/의류의 독립 물리 시뮬레이션은 가져오지 않는다.

| 엎드림·포복 | `Prone.anim`, `ProneCrawl.anim` |
| 사망 | `Death.anim`, 1.25초, 마지막 자세 유지 |
| 시체 수색 | `CorpseLoot.anim`, `CorpseSearch.anim`, 지지점/시체 정렬 |

기본 Idle은 3.5초 호흡 루프다. 루트/Hips의 수평 이동을 고정해 물리 이동과 중복되지 않게 한다. 본 이름의 네임스페이스를 제외하여 맞추지만 범용 리타게팅 시스템은 아니다. 키가 없는 본은 기본 로컬 변환을 따른다. 실제 수평 이동에 맞춰 재생 속도를 조절하고 FBX 보행 주기에 상체를 맞춘다.

총기는 Rifle/Magazine/Bolt/MuzzleFlash OBJ 부품으로 구성된다. 파지 IK는 최종 무기 변환에 두 손을 맞추고 도달 불가능한 목표를 팔 길이로 제한한다. 재장전 중 보조손은 탄창을 따르며, 포복 때에는 조준/발사/재장전 우선 조건을 제외하고 지면 지지 동작을 허용한다. 소총 길이 약 0.943m는 시각 비례 기준이며 정밀한 특정 실총 복제나 성능 데이터가 아니다.

사망은 현재 포즈에서 뒤로 쓰러지는 공통 클립을 적용하고 메시 최저점으로 바닥을 보정한다. 최종 포즈는 고정한다. 주변 벽/계단에 맞춰 전신이 물리적으로 적응하는 래그돌은 없다.

## 13. 렌더링·최적화·사운드

### 13.1 렌더링

OpenGL 3.3 Core, 4× MSAA 요청, sRGB 텍스처와 선형 공간 조명, ACES 톤매핑과 출력 변환을 사용한다. 하늘색 주변광·따뜻한 방향광·약한 보조광을 적용하며 거리 85~235m에서 안개가 배경색으로 수렴한다. MSAA 실제 지원은 드라이버/프레임버퍼에 달려 있다.

산업단지 메시에는 박스·원통·원뿔·불규칙 다면체 삼각형을 만들고 비균일 변환 법선을 보정한다. 환경 전체의 PBR 텍스처/실시간 그림자/동적 국소 광원은 없다. 셰이더 변경 감지는 Debug 500ms 간격이며 Release에서는 생략한다. 재컴파일/링크 실패 시 기존 프로그램을 유지하고 성공 시 uniform 캐시를 무효화한다.

### 13.2 적용된 최적화

- 일반 캐릭터 프레임은 GPU 스키닝이다. CPU는 본 계층/포즈/법선 행렬을 계산하고 매 프레임 전체 정점 복사·업로드를 피한다. 사망 바닥 보정에는 CPU 변형 경로가 남는다.
- 캐릭터 메시의 동일 정점을 병합하고 인덱스/EBO 렌더링을 사용한다. 모델·클립·정적 버퍼·텍스처를 공유하되 포즈·재생 시간·본 행렬은 개별 상태다.
- 본 가중치/행렬 텍스처 버퍼는 unit 6/7을 사용하고 용량 제한을 검사한다. 런타임 가중치 처리와 PMX 변환 단계의 4개 영향 정규화는 서로 다른 단계다.
- 본별 경계를 합쳐 시야를 검사하고 무기 등을 위한 여유를 둔다. 거리 25m 초과 포즈는 최대 30Hz, 60m 초과는 15Hz다. AI/물리/전투 이벤트를 같은 빈도로 줄이지 않는다.
- 맵 정적 메시를 50m 구역·색상별로 합쳐 업로드하고 배치 단위 절두체 검사를 수행한다.
- uniform 위치와 프레임 공통 데이터를 재사용한다. 약한 참조 캐시는 마지막 사용자가 사라지면 자원을 해제한다.

위는 코드상의 최적화이며 FPS/메모리/CPU·GPU 시간의 개선률은 측정되지 않았다. 낮은 포즈 빈도의 추가 보간, 대규모 AI 공간 가속, 완전한 환경 LOD가 구현되었다고 보지 않는다.

### 13.3 오디오

`Core/GunshotAudio`는 Windows XAudio2 기반 합성 소총 총성을 재생한다. 플레이어와 적의 실제 발사 이벤트에 연결되고 최대 16개 음성을 중첩한다. 적 총성은 카메라 방향의 좌우 패닝과 거리 감쇠를 적용한다. 초기화 실패 시 게임 전체를 종료하지 않는 경로가 있다.

발소리·재장전·피격·치료·루팅·환경음의 통합 시스템, 실내외 반향, 벽 차폐와 청각 AI는 후속 범위다.

## 16. 2026-11-10 바닥 가방 착용·은신처 인벤토리 수정

바닥 가방은 3×3 아이템이라 가방이 없는 플레이어의 주머니(6×2)와 조끼(3×2)에 수납할 수 없었다. 기존 F키 줍기는 먼저 수납하는 경로만 사용했고, 바닥 목록의 착용 메뉴와 장비 슬롯 드래그도 실제 착용 처리에 연결되지 않았다.

`LootSystem::EquipNearby(id, player, world, clothingSlot)`를 추가했다. 가까운 바닥 아이템인지, 벽에 가리지 않았는지, 생존 상태·캐릭터별 착용 가능 여부·장비 슬롯 종류를 확인한 뒤 휴대 인벤토리 복사본에 장비 용량을 적용한다. 성공한 경우에만 착용 마스크를 변경하고 바닥 수량을 하나 줄인다. 실패 시 바닥 아이템과 기존 장비는 유지한다. clothingSlot=-1은 종류에 맞는 빈 슬롯을 사용하며, 이미 착용한 장비는 자동 교체하지 않는다.

가방 슬롯이 비어 있으면 F로 가방을 주울 때 바로 착용하여 수납 공간을 확보한다. 인벤토리 바닥 목록에서도 우클릭 ‘착용’ 또는 해당 장비 슬롯으로 드래그하여 직접 착용할 수 있다. 특정 수납칸으로 드래그하는 동작은 기존 수납 규칙을 유지한다. 이미 가방을 착용했다면 F 줍기는 기존처럼 여분 가방의 수납을 시도한다.

은신처 자유 이동 중 I를 누르면 장비 인벤토리가 열리고 커서가 해제된다. 열린 인벤토리/가구 보관함은 I 또는 F로 닫고 이동 시점을 복구한다. Esc는 기존 일시 정지 메뉴를 유지하며, 확인 대화·침대 자세·일시 정지 중에는 기존 입력 우선순위를 따른다.

소스 변경과 문서화를 완료했다. 빌드·테스트·게임 실행은 하지 않았다.

## 17. 2026-11-10 2번 방 새 파밍 자세 테스트

은신처 2번 방 침대 근처에서 F를 누르면 새 파밍 자세를 표시한다. 손과 무릎을 지지하는 캐릭터가 적 역할이며, 플레이어는 같은 방향으로 뒤에서 양 무릎을 꿇고 허리 주변 장비에 손을 댄다. 테스트에는 기존 캐릭터 전환 NPC를 임시로 사용하며 실제 사망·아이템 수색·캐릭터 전환은 발생하지 않는다. 다른 방의 기존 침대 테스트와 레이드 파밍은 유지한다.

전용 자세 데이터는 Assets/Animations/Characters/BedLootEnemy.anim 및 BedLootPlayer.anim이다. 본 회전은 바인드 자세 기준 도 단위이며, 현재는 반복 동작 없이 자세를 유지한다. Root는 이 테스트에서 사용하지 않고 스킨 정점 최저 높이를 기준으로 매트리스 위에 배치한다. AssetCatalog에 등록했고 기존 Animations 런타임 에셋 복사 규칙에 포함된다.

CharacterVisual::SetRoomTwoLootPose(role)는 0=해제, 1=적, 2=플레이어를 선택한다. 적의 양손은 무릎 높이에 IK로 보정한다. FitRoomTwoLootHands(character, target, targetVisual)는 적의 실제 골반 위치를 플레이어 모델 공간으로 변환하여 양손을 장비 수색 위치에 맞춘다. 자세 데이터와 손 보정은 매 프레임 적용하며 무기 표시를 끈다.

테스트 중 이동은 정지하고 침대 전체를 보는 카메라를 사용한다. F 또는 Esc로 종료하면 플레이어·NPC의 위치/방향, NPC 일반 자세, 카메라와 침대 덮개를 복구한다. 테스트 상태는 저장 데이터에 기록하지 않는다.

빌드·테스트·게임 실행은 요청 및 루트 SKILL.md에 따라 수행하지 않았다. 실제 남캐/여캐 모델의 손·무릎 접지, 관절 각도, 침대와의 간섭은 실행 화면에서 아직 확인하지 않았으므로 시각적 완성도는 미검증이다.

### 17.1 참고 자세 불일치 수정

사용자가 제공한 실행 화면에서 적의 몸이 뒤집히고 발이 위로 들리는 문제를 확인했다. 기존 골반/다리의 고정 오일러 각도만으로는 가져온 리그의 본 축을 일관되게 제어하지 못했다. 적의 골반 기본 회전을 중립으로 바꾸고, SkeletalAnimation::AimBoneDirection(joint, child, direction)을 추가했다. direction은 모델 공간 방향이며 부모 전역 회전의 역변환을 통해 관절 회전에 적용한다. 없는 본이나 길이가 없는 방향은 무시한다.

2번 방 테스트는 몸통을 전방으로, 양쪽 허벅지를 아래로, 정강이를 뒤로 정렬한다. 플레이어는 상체를 세우고 양 무릎을 꿇는다. 적 손의 목표는 어깨 앞쪽·무릎 높이이며 팔 길이를 기준으로 팔꿈치 보조 위치를 계산한다. 기존 고정 20 단위 보조 위치를 제거하고 손가락은 전방으로 향하게 했다. 플레이어와 적의 골반 간 앞뒤 간격은 0.75m에서 0.55m로 줄여 수색 손의 도달 거리를 줄였다.

소스 및 문서만 수정했다. 빌드·테스트·실행은 하지 않았고, 수정 후 실제 화면의 관절 비틀림·접지·캐릭터 간 간섭은 아직 미검증이다.

## 18. 구조 대상 위치 테스트 HUD

레이드 진행 중 우측 상단의 기존 시간·위치·탈출구 메시지에 구조 대상 정보를 추가했다. CombatSystem::RescueBody()의 현재 위치를 매 프레임 읽어 X/Y/Z 좌표를 소수점 한 자리로 표시한다. 플레이어와의 3차원 직선 거리(m), 구조 대기/동행 중 상태도 함께 표시한다. 생성되지 않았거나 사망하여 유효한 대상이 없으면 ‘없음 (미생성 또는 사망)’으로 표시한다. 은신처와 레이드 종료 화면에는 추가하지 않는다.

테스트용 표시는 [테스트] 라벨로 구분하며 빌드 구성과 무관하게 표시된다. 저장 데이터·구조 판정·NPC 이동에는 영향을 주지 않는다. 요청대로 빌드·테스트·게임 실행 없이 소스와 문서만 저장했다.

## 19. 수분 초기화·탈수 상태 복구·침대 카메라 회전

은신처 진입 시 공유 프로필의 수분을 100으로 보충한다. 남캐/여캐 및 합류 캐릭터 전환은 이 프로필 수분을 공유하며, 새 Character의 기존 기본값도 100이다. 레이드 중 수분 소모는 유지하고, 수분을 매 프레임 100으로 고정하지 않는다. 다음 출격에는 보충된 프로필 수분을 전달한다. 변경된 프로필은 기존 출격/아이템 사용 등의 저장 경로로 저장된다.

PlayerVitals::Drink()에서 생존 판정 조건을 제거해 은신처의 중상 상태에서도 물을 마실 수 있다. 레이드 InventoryActions의 생존 조건은 유지하여 사망 후 소비를 허용하지 않는다. 수분 0만으로는 원래 출격을 차단하지 않았으나, 탈수 피해로 Alive()가 false인 프로필은 물 섭취와 출격 모두 막혔다. 은신처 진입 시 ‘수분 0이며 생존 불가’인 프로필은 각 부위 체력을 최소 51로 올리고 수분을 보충해 출격 가능 상태로 복구한다. 저장 데이터에 부상 원인이 없으므로 이 조건에는 수분 0에서 전투로 입은 중상도 포함된다. 수분이 남은 일반 중상은 기존 치료/출격 제한을 유지한다.

모든 침대 자세 테스트에서 왼쪽 또는 오른쪽 Alt를 누른 채 마우스를 움직이면 침대 중심 주위를 회전한다. 회전 감도는 픽셀당 0.2도, 수직 각도는 -10~80도이며 Alt를 놓으면 각도를 유지한다. 시작 시 기본 각도로 초기화하고 F/Esc 종료 시 원래 카메라를 복구한다. 포커스가 있을 때만 회전 입력을 받으며 화면 안내에도 Alt 조작을 추가했다.

빌드·테스트·게임 실행 없이 소스 수정과 문서화를 완료했다. 회전 중 벽 가림 등 실제 화면은 미검증이다.

## 20. 2026-11-11 보관함 자동정리 버튼

창고 검색창 옆 자동정리 버튼을 가구 보관함에서도 표시한다. 일반 창고는 기존 창고를, 냉장고·무기고·옷장·의료품 탁자는 현재 열린 방의 해당 보관함만 정리한다. 검색이나 분류로 숨겨진 아이템도 정리 대상이며 툴팁으로 안내한다.

Hideout::AutoArrangeStash(room=-1, furniture=-1)는 두 인수가 -1이면 일반 창고, 유효한 방/가구 인덱스이면 해당 가구 보관함을 선택한다. 기존 Inventory::AutoArrange()를 사용해 큰 면적의 아이템 우선, 같은 면적이면 종류 순으로 배치한다. 수량·아이템 ID는 유지하며 재배치 공간이 부족하면 기존 배치를 유지한다. 정리 후 저장하고 저장 실패 시 이전 상태로 복구한다. 빌드·테스트·게임 실행 없이 코드와 문서를 저장했다.

### 2026-11-04 아이템 점유 크기·투명도·실루엣 변경

이 절은 앞선 2026-11-03 기록의 1스택/1칸 통합 및 고정 슬롯 유지 설명을 대체한다.

#### 원래 점유 크기 복구

- 붕대 1×1, 물 1×2, 탄약 2×1.
- 상의·하의·스포츠 브라·티팬티는 각각 1×2.
- 조끼·헬멧·군화는 각각 2×2, 배낭은 3×3, 소총은 3×1.
- 신규 아이템은 소총 탄창 1×2, 권총 2×1, 권총 탄창 1×1.

창고뿐 아니라 주머니(6×2), 조끼(3×2), 배낭(4×3)의 수납 영역에도 같은 크기를 적용한다. 착용 장비·주무기·부무기의 전용 슬롯은 해당 종류만 받는 기존 규칙을 유지한다. 휴대품 칸 수 표시는 스택 수 대신 실제 점유 면적을 합산한다.

다중 칸 아이템은 한 장의 카드로 그리며 내부 칸에 중복 버튼을 만들지 않는다. 이동·교환 시 전체 점유 영역, 행 경계, 컨테이너 경계를 검사한다. 낱탄은 기존처럼 최대 30발씩 묶으며, 30발 묶음 하나가 2×1 영역을 차지한다. 탄창 삽입·분리·채우기·빼내기도 새 공간 규칙을 사용한다.

#### 기존 세이브 처리

저장 형식은 v11로 구분한다. v10을 읽을 때 기존 위치에 새 크기로 넣기를 시도하고, 충돌하면 빈 영역에 재배치한다. 휴대품에 들어가지 않는 물품은 창고로 옮기며, 이관 과정에서만 필요에 따라 창고를 한 행씩 확장해 보존한다. v1~v9도 새 크기로 재배치한다. v11은 저장된 위치와 전체 영역 겹침을 검사하여 읽는다. 이번 작업에서 실제 사용자 세이브를 실행·변환하지 않았으며, 다음 게임 로드/저장 경로에 적용된다.

#### 반투명 화면

NPC 가까이에서 F를 누르면 기존 캐릭터 변경 확인 창을 열고, 예를 선택하면 전환 내용을 저장한다. 구조해 합류한 여성은 3번 방부터 순서대로 배치되고 각 방은 가구 보관함·캐릭터 상호작용과 함께 열린다. 구조 인원과 교체할 때는 상호작용한 방을 확인 창까지 유지해 해당 방 인원만 내보내고, 전환된 플레이어의 반대 성별 캐릭터는 기본 배정 방으로 돌아간다. Y 키는 테스트용으로 3번 방 구조 인원을 내보내고 해당 방을 잠근다. 방 1 침대 가까이에서 F를 누르면 기본 파밍 자세, 방 2 침대에서는 추가 파밍 자세를 테스트하며 F 또는 Esc로 원래 상태를 복구한다. 방에 들어가면 카메라가 1인칭으로 부드럽게 전환되고 방 밖에서는 3인칭으로 돌아온다. 전환 중에는 직전 프레임 카메라 위치에서 새 위치로 시간 기반 보간하며, 3인칭 복귀가 거의 끝날 때까지 캐릭터 모델을 숨겨 화면 팝을 줄인다. 의자와 의료품 테이블은 문과 침대 사이로 옮겼다.

은신처 기본 안내 패널을 제거하고, 의료품 테이블을 재배치된 위치에서도 F로 상호작용할 수 있도록 탐지 범위를 수정했다. 신규 및 기존 프로필에 방별 기본 의상, 소총·권총·탄창·탄약, 물·전투식량, 붕대를 각각 옷장·무기고·냉장고·의료품 탁자에 한 번 지급한다. 저장 형식은 HIDEOUT 17이며 이전 버전의 물자는 보존한 뒤 초기 보관품을 추가한다. 가구 보관함 우클릭 메뉴에서 탄창 채우기/비우기, 스택 분할, 아이템 판매와 소비품 사용을 제공한다.

#### 2026-11-09 레이드 구조 시스템

출격 시 구조 인원이 남아 있으면 무장하지 않은 여성이 무작위 유효 위치에 생성되어 비공격 상태로 배회한다. F키 상호작용 후 데려가기를 선택하면 플레이어를 따라오며, 이후 적 AI의 공격 대상이 된다. 플레이어와 동행자가 함께 탈출 구역에 있어야 탈출 시간이 진행된다. 생존해 함께 탈출하면 결과 화면에 두 캐릭터를 나란히 표시하고 `여캐 (합류함)`으로 기록한다. 최대 두 명을 구조할 수 있고, 빈 방에 배치해 방별 점유 상태를 저장한다. 교체 상호작용은 정확히 선택된 방의 인원을 내보내며, Y 키는 3번 방 인원만 내보내고 문을 잠그는 테스트 기능이다. HIDEOUT 19에 구조 인원 및 방별 점유와 모든 방 보관함을 저장하며 기존 v1~v18을 변환한다.

2026-11-10 이전 작업 기록(구조 정리 커밋 27ad256): Debug | x64 전체 빌드가 성공했고 실행 파일과 88개 런타임 자원 복사를 확인했다. 별도 임시 저장 폴더를 지정한 시작 스모크 테스트에서 은신처 초기화와 프로필 생성까지 확인한 뒤 임시 자료를 제거했다. 플레이 흐름 전체는 수동 검증하지 않았다. Python 도구 9개 파일은 구문 검사를 통과했으나 `--help` 실행은 현재 환경에 NumPy가 없어 확인하지 못했다.

#### 완료 내용

- **소스와 빌드 산출물:** 게임 코드를 `src/`로 이동하고 솔루션 `Project_Tarkov.sln`은 저장소 루트에 둔다. 중간/실행 파일은 `Project_Tarkov/x64/<Configuration>/`에 생성한다. 루트 `.gitignore`는 PDB 등 컴파일 부산물을 무시하되, `Assets/Models/Weapons/*.obj` Wavefront 모델은 보존한다.
- **경로와 프로필:** `RuntimePaths`와 `AssetCatalog`가 에셋/세이브 경로를 작업 디렉터리 변경 없이 제공한다. 에셋은 저장소의 `Assets/` 또는 패키지 실행 파일 옆에서 찾고, `TARKOV_ASSET_ROOT`·`TARKOV_SAVE_ROOT`는 절대 경로 오버라이드다. 기존 세이브를 발견하면 그 자리에서 계속 사용하며 자동 이동·병합·덮어쓰기는 하지 않는다. 실행 파일 옆 프로필이 있으면 이를 우선한다. 이 프로필이 없고 과거 후보가 여러 개일 때 명시적 저장 경로를 요구한다. `여캐` 경로와 UTF-8 로딩은 유지한다.
- **Visual Studio 목록:** `src/Project_Tarkov.vcxproj`와 `.filters`를 현재 파일 구조에 맞추고, 소스·필터 항목의 누락이나 불일치가 없도록 동기화했다.
- **책임 분리:** `Game/Hideout`, `Game/Raid`, `Game/Inventory`, `Game/UI`, `Game/World`로 구현을 구분했다. 은신처/레이드 장면, 은신처·레이드·인벤토리·결과 UI, 인벤토리 명령을 별도 파일로 나눴다. 공통 메시/충돌 생성은 `Graphics/WorldGeometry.*`로 분리했다.
- **외부 맵 데이터:** 산업단지 스폰·탈출구·건물·적 위치는 `Assets/Maps/IndustrialZone/locations.layout`, 은신처 방/가구/외벽은 `Assets/Maps/Hideout/`의 layout·parts 파일에서 읽는다. 로더는 누락·중복·잘못된 값과 불완전한 배치를 오류로 보고한다.
- **에셋과 원본:** 네 locomotion FBX를 `Assets/Animations/Characters/Locomotion/`으로 이동했다. 게임 런타임 에셋은 `Assets/`, VRM/VRoid/Blender 원본과 파생 제작 자료는 `ArtSource/Characters/`에 둔다. 원본 파일은 삭제하지 않았다. 런타임 복사 대상은 프로젝트 파일에서 명시한다.
- **도구와 문서:** 캐릭터 스크립트는 `Tools/Characters/`, C++ 자세 검증 소스는 `Tools/Validation/`에 둔다. 공통 경로 도우미는 저장소 루트 기준 경로와 기본 입력/출력 위치를 제공한다. `Tools/README.md`에 사용법·옵션·의존성을, `docs/IMPLEMENTED.md`에 현재 경로·구조·저장 정책을 기록했다.

솔루션 폴더를 다시 옮기거나 `x64/Debug` 빌드 위치를 변경하는 것은 이번 범위가 아니다. 실행 파일 옆 프로필이 없으면서 여러 과거 프로필이 남아 있으면 `TARKOV_SAVE_ROOT`로 사용할 프로필을 지정해야 한다. 문서의 기능별 우선순위 목록은 아직 구현되지 않은 게임 기능에 대한 계획이며, 이 구조 작업으로 완료 처리하지 않는다.
