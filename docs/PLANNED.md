## 1. 비교 기준과 조사 출처

### 1.1 원작과 프로젝트의 관계

원작은 장비를 준비하고 PMC/Scav가 있는 레이드에서 전리품을 확보해 탈출하는 FPS이며 온라인 PvP/협동 기능을 제공한다. 개발사 설명에는 출혈·부위 손상도 명시되어 있다. 현재 프로젝트는 그 반복 구조의 로컬 싱글플레이 부분을 구현한 상태다. [개발사 Steam 제품 설명](https://store.steampowered.com/app/3932890/Escape_from_Tarkov/)

공식 Steam 공지에서 2026-10-06의 **1.2.0.0** 공지를 확인했다. 이 버전의 PvE PMC 봇 변경은 관심 지점 이동과 진영 관계를 다룬다. 같은 공지 목록의 **1.1.0.0**에는 거래액 기반 충성도 요구 제거, 일부 건설 재료의 FIR 요구 완화, 무기 빌드 기능의 초기 개방, 모드별 보험 차이가 기록되어 있다. 오래된 가이드의 수치를 그대로 현행 규칙으로 채택하지 않는다. 이는 모든 후속 핫픽스까지 확인했다는 뜻은 아니다. ## 3. 먼저 해결할 현재 구현의 빈틈

아래 P0는 새로운 원작 기능을 추가하기 전에 현재 반복 플레이가 끊기지 않도록 하는 작업이다. 코드 관찰과 실행 재현이 필요한 가설을 구분한다.

### P0-01. 사망 이후 재기 경로

**현재 근거:** `PlayerVitals::Alive`, `Hideout::HealBodyPart`, `RaidScene::StartRaid`. 죽은 상태로 귀환하면 치료가 필요하지만 붕대가 없고 상점/자동회복도 없을 수 있다. 장비·물·탄약 소진도 같은 반복 플레이 문제다. 무기 없이 출격 가능하다는 것만으로 사망 상태 출격 차단이 해결되지는 않는다.

**개발:** 은신처 기본 회복 또는 자산 부족 시 제한적 재기 보급을 우선 제공한다. 재사용 대기/지급 기록을 저장해 화면 재진입으로 복제되지 않게 한다. 이후 Scav 모드/상점으로 자연스럽게 연결한다. 구체적 대기 시간과 지급량은 프로젝트 밸런스 값으로 정한다.

**완료:** 붕대 0·소총 0·탄약 0·사망 상태의 프로필에서도 정상 UI만으로 다시 플레이할 수 있다. 재시작/반복 클릭으로 지원품이 중복되지 않는다.

### P0-02. 저장 실패와 정산 일관성

**현재 근거:** `Hideout::Save/Recover/Depart`, `RaidScene::FinishRaid`, `RaidResultScene`. 출격 전 보호 창고 저장과 실패 롤백은 있으나 성공 장면으로 이동할 때 회수 저장 실패 안내/재시도 흐름은 충분한지 확인해야 한다.

**개발:** 정산 상태를 `미반영→메모리 반영→저장 완료`로 구분하고 결과 화면에서 실패 이유와 재시도를 제공한다. 레이드 식별자/정산 식별자를 저장하여 중복 적용을 차단한다. 이전 저장 백업과 v1~v9 이관 테스트 자료를 준비하고 작업 디렉터리 의존 저장 위치를 고정 사용자 경로로 옮긴다.

**완료:** 쓰기 거부·임시 파일 실패·교체 실패·종료 직전 실패에서 장비가 복제/유실되지 않는다. 저장되지 않은 회수품이 있는데 저장 완료처럼 안내하지 않는다. 손상된 파일은 보존하고 복구 선택지를 제공한다.

### P0-03. 개발용 입력과 정식 조작

**현재 근거:** T가 빌드 구분 없이 탈출구 이동, Q가 애플리케이션 종료다.

**개발:** T 순간이동을 개발 빌드/명시적 디버그 설정에 한정한다. 종료는 메뉴로 이동하고 Q/E를 기울이기에 사용할 수 있도록 액션별 키 설정을 도입한다. 초기화 버튼과 설정 저장, 충돌 키 안내를 제공한다.

**완료:** 배포 빌드에서 T로 탈출 시간을 우회할 수 없고, 재지정한 키가 HUD 안내·메뉴·게임 입력에 일관되게 적용된다.

### P0-04. 공정한 전투와 탄약 보존

**현재 근거:** AI는 1.2초마다 부위에 직접 40 피해를 주며 탄약을 소모하지 않는다. 시체 소총 획득은 30발을 설정한다. 결과 머리 표시는 피해 배율과 무관하다.

**개발:** 최소한 플레이어/적에게 동일한 탄약·발사·피해 이벤트 경로를 적용한다. 적도 남은 탄약·재장전·반응 지연을 갖게 한다. 시체의 소총/탄창 상태를 그대로 이전한다. 기록의 표시 부위와 실제 피해 부위를 통일한다.

**완료:** 전투 전후 `소지 탄약+탄창+약실+월드/시체 탄약+발사/소비량`이 일치한다. 엄폐 뒤 직접 피해, 무한 AI 탄약, 소총 회수 시 잔탄 재생성이 없다.

### P0-05. 카메라·수색·결과 회귀

**현재 근거:** 3인칭은 바닥 높이 제한만 있고 월드 충돌은 없다. 수색은 캐릭터 위치/카메라를 바꾸는 경로다. 성공 결과는 시작 대비 순증 수량이며 처치 시계와 레이드 시계가 다르다.

**개발:** 카메라 스윕, 수색 진입 실패 시 원상 복구, 종료 복귀 위치 재검사, 통일된 레이드 이벤트 시각을 추가한다. 결과는 획득/사용/분실/회수 항목을 구분한다.

**완료:** 좁은 문·천장·시체 밀집·공중/경계에서 카메라 벽 관통이나 잘못된 복귀가 없고, 수색 중 사망/포커스 상실에도 조작이 복구된다. 긴 프레임에서도 기록 시간이 설명 가능하다.

## 4. 전투·생존·인벤토리

### P1-01. 부위 체력과 사망 규칙

**원작 비교:** 커뮤니티 건강 자료의 PMC 기본값은 머리 35, 흉부 85, 복부 70, 양팔 각각 60, 양다리 각각 65로 합계 440이다. 파괴된 사지는 일반 회복과 구분되고 수술 대상으로 다뤄진다. 이는 현재 각 부위 100/평균 체력/머리+몸통 합산 사망과 다르다. 세부 전이 피해와 예외 사망 규칙은 별도 검증이 필요하다. [S4](https://www.tarkovproject.app/guides/health)

**요구사항:** `BodyPartDefinition`에 기본/현재 최대 HP, 주요 부위 여부를 두고 `BodyPartState`에 현재 HP·파괴·상태이상을 둔다. 현재 Pelvis를 원작의 Stomach와 대응시킬지 명시적으로 결정한다. 초기 제안은 흉부/머리 치명타와 사지 파괴를 분리하고 정확한 원작 전이 계수는 확인 전 하드코딩하지 않는 것이다.

피격 이벤트에 공격자·탄종·부위·거리·방어 판정을 전달한다. 플레이어/적이 같은 DamageResolver를 사용하고 HUD는 합계/최대치와 부위를 별도로 표시한다. 구버전 0~100 값은 비율 변환 등 이관 규칙을 정해 저장 업그레이드 시 처리한다.

**완료:** 머리/흉부/팔/다리의 같은 탄환 피격 결과를 설명할 수 있다. 파괴 부위에 붕대를 사용해 즉시 정상 사지로 돌아오지 않는다. 기존 프로필을 불러오는 것만으로 예기치 않게 사망하지 않는다.

### P1-02. 의료와 생존 자원

**원작 비교:** 경출혈과 중출혈이 분리되며 붕대와 중출혈 대응 의료품은 용도가 다르다. [S5](https://wikiwiki.jp/eft/%E4%BD%93%E5%8A%9B)

**요구사항:** 초기에는 경출혈·중출혈·골절·통증·부위 파괴를 구분한다. 붕대는 경출혈, 지혈 도구는 중출혈, 구급품은 HP, 부목은 골절, 진통제는 일시 증상 억제, 수술 도구는 허용된 파괴 부위 복구라는 프로젝트 규칙으로 설계한다. 도구별로 허용 효과·사용 횟수/자원·사용 시간·부위·취소 시 소비 시점을 데이터화한다.

수분과 별도로 에너지/음식을 추가한다. 현재 스태미나를 에너지로 재사용하지 않는다. 과체중·부상·달리기가 자원에 주는 효과는 매개변수로 분리한다. 치료 중 사격/전력질주·피격·UI 닫기·포커스 상실 시 처리와 완료 직전 취소를 정의한다.

**완료:** 동일 상처에 잘못된 도구를 사용하면 이유를 보여주고 소비하지 않는다. 치료 효과와 수량 차감은 한 번만 발생한다. 출혈 중 UI를 열어도 피해는 지속한다. 값은 음수/최대치 초과/NaN으로 저장되지 않는다.

### P1-03. 탄창·약실·총기 인스턴스

**현재 차이:** 소총은 boolean+잔탄 정수이고 탄창은 소모품 인스턴스가 아니다. 실제 게임의 탄창 준비 경험과 차이가 크다. [S11](https://www.pcgamer.com/games/fps/escape-from-tarkov-review/)

**요구사항:** `WeaponInstance`에 ID·무기 정의·장착 탄창 ID·약실 탄종·사격 모드·내구도를, `MagazineInstance`에 용량·허용 구경·순서 있는 탄 목록을 둔다. 초기에는 기존 소총과 단일 구경으로 시작한다. 탄창 교체와 탄창 내부 탄 넣기를 분리하고 일반/빠른 재장전의 빈 탄창 보관 실패 규칙을 명시한다.

무장 슬롯→휴대품→창고→시체 사이에서 같은 인스턴스를 이전한다. 현재의 `TakeCorpseRifle`이 생성하는 30발을 실제 상태 이전으로 바꾼다. 잔탄 확인은 재장전과 독립 액션으로 만들고 정밀 수량/대략적 문구 중 프로젝트 표시 방침을 정한다.

**완료:** 30발 탄창+약실 1발, 약실만 남은 상태, 빈 탄창, 호환되지 않는 탄약, 재장전 취소, 만원 휴대품, 사망 중 장전에서 수량과 인스턴스가 보존된다.

### P1-04. 탄도·방어구·명중

**원작 비교:** 탄약 관통력과 방어 등급/남은 내구도가 관통에 영향을 준다. [S3](https://escapefromtarkov.fandom.com/wiki/Ballistics)

**요구사항:** 먼저 탄약 정의를 피해·관통·속도·방어구 손상·구경으로, 방어구를 보호 부위·등급·최대/현재 내구도·재질로 나눈다. 헬멧/조끼 외형과 보호 기능을 연결한다. 초기 탄종 2개·방어구 2등급부터 동일한 표적에 대한 차이를 검증한다. 이 숫자는 프로젝트 제안이다.

단계 1은 기존 광선을 유지한 부위/방어 판정, 단계 2는 시간 기반 투사체와 이전→현재 위치 구간 충돌, 단계 3은 지형 재질·도탄·파편 확장이다. 본 기반 단순 히트박스를 우선하고 매 프레임 정밀 스킨 삼각형 충돌은 성능 측정 없이 도입하지 않는다. 총구가 벽 안에 있는 사격도 검사한다.

**완료:** 같은 탄종은 같은 방어 조건에서 재현 가능한 결과를 낸다. 낮은 FPS에서 얇은 벽을 통과하지 않는다. 화면 명중 표시·HP·방어 내구도·처치 로그가 같은 판정을 사용한다. 확률형 관통은 고정 시드로 회귀검사가 가능하다.

### P1-05. 휴대 격자와 컨테이너

**요구사항:** 현재 창고 배치 알고리즘을 재사용 가능한 `GridInventory`로 분리하고 휴대 가방/리그/주머니를 각각 컨테이너로 관리한다. 항목마다 고유 ID, 정의 ID, 수량, 회전, 위치, 부모 컨테이너, 내구도/자원을 둔다. 소총도 같은 소유권 모델에 포함한다.

90도 회전, 스택 분할/합치기, 빠른 이동, 탐색/정렬을 추가한다. 가방 속 가방 허용 여부, 자기 자신/조상 컨테이너로 이동 금지, 장비 제거 시 내부 물품의 귀속, 퀘스트 물품 제한을 정의한다. 외형 의류와 기능성 방어구는 별도 속성으로 다룬다.

**완료:** 이동·회전·합치기 실패 시 전 상태가 유지된다. 반복 드래그로 아이템이 복제되지 않고 중첩 컨테이너에 순환이 생기지 않는다. 회전한 채 재시작해도 배치가 유지된다. 과거 초과 재고는 삭제 없이 이관된다.

### P1-06. 총중량과 움직임 비용

**요구사항:** 휴대품뿐 아니라 착용 장비·무기·탄창·내부 컨테이너를 포함한 총중량을 계산한다. 경량/과중량 상태에 이동 가속·최고 속도·스태미나 소비/회복·점프 가능 여부를 연결한다. 제한은 제안된 프로젝트 값으로 표시하고 원작 정확 수치로 소개하지 않는다.

**완료:** 같은 아이템을 창고에서 장착 슬롯으로 옮기는 것만으로 무게가 사라지지 않는다. 무게 제한 직전/직후와 배낭 버리기의 결과가 즉시 반영된다. UI 수치와 실제 이동 계산이 일치한다.

## 5. AI·맵·루팅·탈출

### P1-07. AI의 인지·이동·전투

**원작 비교:** 1.2.0.0의 PvE 변경은 PMC 봇이 관심 지점과 임무 구역으로 이동하고 진영 관계를 다르게 처리한다고 설명한다. 현재의 왕복 순찰 5명과는 행동 범위가 다르다. 원작 내부 AI 알고리즘을 공개된 것으로 가정하지 않는다. [S2](https://steamcommunity.com/app/3932890/allnews/?l=english)

**요구사항:** 감지에 시야각·거리·가림·노출 시간·청각 이벤트를 추가한다. 마지막 관측과 마지막 소리를 분리하고, 관측하지 못한 플레이어 좌표를 추적 목표로 직접 사용하지 않는다. 격자 A* 또는 NavMesh 경로를 만들고 문·좁은 통로·실내외를 연결한다.

순찰→의심→탐색→접근→엄폐 교전→재장전/후퇴→사망 상태를 정의한다. 적 반응 지연·조준 오차·버스트·탄약·피격 반응을 플레이어와 공유된 전투 규칙 위에서 동작시킨다. 초기에는 일반 순찰병과 고정 경비의 두 역할을 제안한다. 보스와 복잡한 진영 외교는 후순위다.

**완료:** 벽 뒤 걷기는 보지 못하고 큰 소리에는 마지막 소리 위치를 조사한다. 중앙 공장 안팎의 지정 경로를 막힘 없이 이동한다. 탄약 소진 후 공격이 중지되고 시체는 공격하지 않는다. 난이도는 즉시 확정 피해가 아닌 인지/조준/전술 값으로 바뀐다.

### P1-08. 루팅 분포·컨테이너·출처

**현재 차이:** 모든 건물이 같은 11종 균등 추첨을 사용하여 구역을 선택할 이유가 작다.

**요구사항:** `LootTable`을 구역·컨테이너 종류·등급·빈 확률·수량 범위로 분리한다. 창고는 공구/식량, 야적장은 탄약/부품, 공장은 고급 부품, 관리동은 의료/문서/열쇠, 발전소는 연료/전자, 외곽은 기본 보급품으로 차별화한다. 처음에는 현 20곳의 품질을 검증한 뒤 100곳 목표로 늘린다.

상자/서랍/가방에 열기·수색 시간·발견 슬롯·중단/재개 상태를 추가한다. 아이템에 출처와 레이드 ID를 저장해 퀘스트 납품 판정의 기반을 만든다. FIR은 프로젝트 규칙을 명시적으로 정의하며 “레이드에서 주웠으면 모든 모드에서 항상 납품/판매 가능”으로 단순화하지 않는다.

**완료:** 같은 시드로 같은 배치가 재현된다. 재개방으로 새 물건이 생기지 않는다. 컨테이너 만원·수색 도중 사망·거리 이탈에서 소유권이 유지된다. 구역별 표본 드롭률을 출력해 실제 분포를 점검한다.

### P1-09. 스폰과 조건부 탈출

**요구사항:** 현재 2개 스폰의 무작위 선택을 안전도 평가 후보 목록으로 확장한다. 지면 지지·몸체 공간·AI 시야·첫 엄폐까지 거리·탈출 동선을 검사한다. 멀티플레이 이전에는 다른 인간 플레이어 간 최소 거리보다 AI/지형 안전을 우선한다.

현재 X1/X2는 유지하고 기존 자체 설계의 X3 서쪽 배수로, X4 남쪽 화물차를 추가 제안한다. X3는 열쇠 또는 전원 조건 및 12초 대기, X4는 1회 사용·작동 후 60초 대기·10초 탑승 판정이다. **이 이름·위치·시간은 원작 탈출구의 복제가 아니라 기존 프로젝트 설계다.** 실제 맵 비교 시에는 [Customs 자료](https://wikiwiki.jp/eft/CUSTOMS)의 지도별 조건을 별도로 확인한다.

탈출구에 ID·범위·배정·필요 조건·활성/잠김/대기/소진 상태·남은 사용 횟수를 둔다. 조건 소모 시점, 탑승 가능 창, 동시 사망/시간 초과의 우선순위를 정의한다. HUD에 닫힘 이유를 제공한다.

**완료:** 잘못 배정된 출구/키 없음/전원 없음/소진 상태에서는 탈출하지 않는다. 조건을 충족하면 정확히 한 번 정산한다. 범위 이탈·재진입과 제한 시간 경계 결과가 일정하다.

### P2-01. Industrial Zone 완성도

기존 500×500m/25분을 우선 유지한다. 원작 맵의 실제 크기나 레이드 시간으로 소개하지 않는다. 중앙 고위험/고보상과 외곽 우회라는 현재 자체 설계의 의도를 플레이 결과로 검증한다.

| 구역 | 남은 설계/작업 | 확인 기준 |
| --- | --- | --- |
| 창고 A | 작은 사무실·통로·열리는 창고 상자 | 출입구 두 곳과 루팅 접근이 유지됨 |
| 야적장 B | 40개 컨테이너 일부 개방·차별화 루팅 | 장거리 일방 시야와 막힌 동선 점검 |
| 공장 C | 2층·계단·부속 건물·희귀 물품 | 수직 교전의 카메라/AI/충돌 검증 |
| 관리동 D | 2층·경비실·문서/키 방 | 문/키·임무·실내 경로 연결 |
| 발전소 E | 상호작용 전원·전자/연료 | 탈출 조건과 월드 상태 연결 |
| 외곽 F | 실제 배수로·고저차·우회 루팅 | 수풀 시각 가림과 충돌 의미 구분 |

기존 목표인 진입 건물 9~12개, 주요 실내 25~35개, 엄폐 구조물 60~90개, 루팅 90~120곳은 밀도 참고치로 유지한다. 현재 이미 생성된 장식 개수를 이 기능 목표의 완료 수량으로 세지 않는다. 통로의 너비·계단 이동·층별 AI 길찾기를 먼저 해결한 뒤 환경을 늘린다.

## 6. 경제·퀘스트·은신처·성장

### P1-10. 상인과 최소 경제

**원작 비교:** 상인별 물품, 물물교환, 수리/보험 등 서비스와 플리마켓이 존재한다. [S7](https://escapefromtarkov.fandom.com/wiki/Trading)

**요구사항:** 초기 로컬 상인 2역할(장비/탄약, 의료/보급), 통화 1종, 구매·판매·교환·회복 서비스를 제안한다. 가격·재고·재입고·구매 제한은 데이터화한다. 상인 평판/등급은 저장하지만 오래된 거래액 조건을 원작 현행 규칙으로 재도입하지 않는다. 구매 가능 이유와 잠금 해제 조건을 표시한다.

구매는 돈·창고 공간·상품 수량 검증 후 원자적으로 이전한다. 판매는 장착/컨테이너 내부 아이템과 임무 물품을 검사한다. 수리 비용/내구도 변화를 미리 보여준다. 플리마켓은 먼저 NPC 가격 시뮬레이션과 UI만 검토하며 사용자 간 실제 시장은 온라인 단계로 분리한다.

**완료:** 돈 부족/창고 만원/재고 소진/저장 실패에서 돈과 물건이 동시에 보존된다. 재시작해도 재고/평판이 유지된다. 최소 보급을 반복 구매할 수 있어 전리품에 사용 목적이 생긴다.

### P1-11. 퀘스트와 경험치

**원작 비교:** 퀘스트에는 진행과 납품, 별도 취급되는 퀘스트 물품이 있다. [S8](https://escapefromtarkov.fandom.com/wiki/Quests)

**요구사항:** 초기 제안은 수집 2·처치 2·구역 방문 1·조건부 탈출 1의 6개다. 임무 정의에 선행 조건·목표·누적/단일 레이드 구분·생존 요구·보상·상인 평판을 둔다. 상태는 잠김/수락 가능/진행/목표 달성/보상 수령으로 나눈다.

게임 이벤트를 통해 진행시키고 HUD 표시와 저장을 분리한다. 수집은 발견과 납품을 구분하고 납품 시 물품을 차감한다. 사망 시 유지/초기화와 전용 물품 보관 정책을 정의한다. 처치/탐색/생존/임무 완료 XP를 별도 이벤트로 기록하고 중복 지급을 차단한다.

**완료:** 임무 미수락 시 행동, 이미 완료한 임무, 재접속, 수령 직전 저장 실패, 같은 적 중복 사망 이벤트가 보상을 복제하지 않는다. 처치 로그의 건수와 퀘스트 조건의 건수가 일치한다.

### P2-02. 은신처 시설과 제작

**원작 비교:** 은신처는 시설 건설과 제작, 전력/연료, 레이드 밖 회복을 제공하며 결과물은 공간을 확인해 수령한다. [S6](https://wikiwiki.jp/eft/HIDEOUT)

**요구사항:** 초기 시설은 발전기·의료 시설·작업대·보급 시설·창고 확장으로 제안한다. 시설별 레벨·선행 시설·재료/돈·건설 종료 시각·효과를 저장한다. 제작은 재료 예약/소비→진행→완료/수령 대기→수령의 상태를 갖는다. 초기에는 2D 메뉴로 규칙을 완성하고 3D 은신처 탐색은 이후에 붙인다.

전원 차단/연료 소진 시 정지 또는 감속 정책을 명확히 정한다. 실제 원작 일부 예외를 확인하지 않고 모든 제작에 동일 조건을 강제했다고 설명하지 않는다. 무기 프리셋 UI 해금과 작업대 제작 기능도 별개로 다룬다. 오프라인 진행 시간을 허용하면 저장된 UTC 시각과 최대 인정 시간, 시스템 시계 역행 대응을 정한다.

**완료:** 재료가 부족하면 시작되지 않고 제작을 재개해도 재료를 두 번 소비하지 않는다. 창고가 차면 결과물을 시설에 보관한다. 종료/재시작·시계 변경·연료 소진으로 결과물이 복제되지 않는다.

### P2-03. 재기용 Scav 출격

**원작 비교:** 플레이어 Scav는 무작위 지급 장비로 출격한다. [S9](https://escapefromtarkov.fandom.com/wiki/Scavs)

**요구사항:** PMC 프로필과 별도 임시 장비/상태를 만들고, 성공 시 획득품을 본 창고로 이전하는 수령 화면을 제공한다. 재사용 대기와 결과 수령 상태를 저장한다. 싱글플레이 첫 단계는 별도 새 레이드여도 되며, 원작처럼 진행 중 온라인 세션에 합류한다고 설명하지 않는다.

**완료:** Scav 사망이 PMC 출전 장비를 지우지 않는다. 성공품 수령 중 만원/저장 실패/종료 후에도 한 번만 이전한다. 대기 시간의 재시작 우회가 없다.

### P2-04. 보험·보호 수납·성장

보험은 원작 모드에 따라 차이가 있으므로 기본 기능으로 일괄 약속하지 않는다. 공식 1.1.0.0 공지는 PvP Season과 다른 모드의 보험을 구분한다. [S2](https://steamcommunity.com/app/3932890/allnews/?l=english)

**프로젝트 제안:** 싱글플레이 보험을 도입하면 보험 대상 인스턴스·분실·회수 가능 여부·반환 대기·수령 기한을 저장한다. 전리품이 영구적으로 남지 않는 현재 레이드 수명에서 회수 확률을 어떻게 정할지 먼저 결정한다. 안전 컨테이너는 허용 유형·면적·레이드 중 추가 가능 여부·사망 보존 규칙을 독립 정의한다.

성장은 우선 캐릭터 레벨과 이동/수색/무기 취급 숙련의 소수 항목만 제안한다. 경험치 곡선·효과 상한·반복 행동 제한을 데이터화한다. 원작 전체 스킬 수나 보너스 계수를 확인 없이 복제하지 않는다.

**완료:** 보험 반환/보호 슬롯/퀘스트 납품 사이 중복 소유가 없다. 성장 보너스가 수량 보존·방어/생존 규칙을 우회하지 않는다. 리셋과 저장 이관 시 효과가 중복 적용되지 않는다.

## 7. 조작·표현·품질·배포

### P1-12. 전술 조작과 카메라

원작의 Q/E 기울이기는 현재 프로젝트의 Q 종료와 충돌한다. [S10](https://escapefromtarkov.fandom.com/wiki/Controls)

**개발:** 키 바인딩 이후 좌우 기울이기·걷기 속도 단계·조준 이동·숨 참기를 순차 도입한다. 애니메이션만 이동시키지 말고 눈/총구/히트박스/충돌을 함께 연결한다. 1인칭 카메라의 월드 충돌과 신체 회피를 함께 처리하고, 수색을 1인칭 유지 또는 3인칭 연출로 할지 옵션/프로젝트 방향을 명시한다.

**완료:** 기울여도 머리/총구가 벽을 뚫지 않으며 화면에 보이는 총구와 판정이 일치한다. Alt 자유 시점 종료 후 조준 방향이 변하지 않는다. 달리기·포복·재장전·치료 전환에 입력이 남지 않는다.

### P1-13. 사운드와 감지 정보

**개발:** 발소리(재질/속도/자세), 점프·착지, 재장전/빈 탄창, 피격·호흡, 치료·루팅, 실내외 환경음을 추가한다. 사운드 이벤트를 청각 AI에 전달하되 오디오 음소거가 AI 인지까지 끄지 않도록 게임 이벤트와 재생을 분리한다. 거리 감쇠/벽 차폐/수직 층 구분을 적용하고 음량·동적 범위 설정을 저장한다.

**완료:** 자기 발소리와 적 발소리의 위치가 설명 가능하고 벽/층을 사이에 둔 소리가 무조건 같은 크기로 들리지 않는다. 동시에 여러 사격/발소리가 발생해도 오류 없이 보이스 한도를 지킨다. 오디오 장치 없는 PC에서도 진행 가능하다.

### P2-05. 환경 그래픽과 캐릭터 품질

**개발:** 환경 재질/텍스처, 그림자, 실내 광원, 적 식별, 피격/탄흔/연기, 먼 거리 LOD를 단계적으로 추가한다. 먼저 밝은 야외와 어두운 실내의 적 시인성을 확보한다. 비/안개/주야는 시야·AI·오디오까지 연결할 수 있는 단계에 도입한다.

캐릭터는 7기본 자세 외에도 조준·재장전·치료·기울이기·부상 이동의 조합을 검증한다. 옷 뚫림, 군화/발 지면 접촉, 양손 파지, 팔꿈치, 사망 시 벽 겹침을 개선한다. 원작의 콘텐츠량보다 현재 한 모델/한 소총의 일관성을 우선한다.

**완료:** 동일 시나리오를 1/3인칭·다양한 FOV·해상도에서 비교한 캡처와 프레임 시간 기록이 있다. 그래픽 품질을 낮춰도 게임 판정과 가림 규칙이 달라지지 않는다.

### P1-14. 검증·성능·배포

**개발:** 기존 에셋 검증 도구에 더해 수량 보존, 저장 마이그레이션/실패, 타이머 경계, 피해·치료, 경로 탐색을 검증하는 의미 있는 자동 검사를 구성한다. 실제 게임 통합 시나리오를 별도로 수행한다. 과거 자세 렌더 검사 통과를 전체 게임 통과로 재사용하지 않는다.

목표 하드웨어를 정하고 Release에서 평균/상위 프레임 시간, CPU/GPU 시간, 메모리, draw call, AI 갱신 비용을 기록한다. 1080p 60fps는 우선 제안 목표이며 이미 달성한 수치가 아니다. 현재 5명→계획 12명으로 확장할 때 공간 질의 가속, AI 갱신 배분, LOD 필요성을 측정한다.

배포 패키지는 EXE·DLL·Assets·런타임 요구사항·저장 위치·버전 정보를 포함한다. 개발 도구 없는 Windows PC에서 시작/저장/반복 레이드/종료를 확인하고 누락 자원 오류를 사용자에게 보여준다.

**완료:** 지정 하드웨어에서 측정 기록이 있고 배포본으로 반복 루프가 통과한다. 게임 파일 교체가 저장 데이터를 지우지 않는다. 누락 에셋/오디오/저장 권한 문제의 실패 방식이 명확하다.

### P3-01. 온라인 협동/PvP

온라인은 기존 설계의 6~8명 상수만으로 구현되지 않는다. 현재 네트워크 전송·서버 권한·세션·동기화가 없으므로 별도 프로젝트 단계로 취급한다.

**개발:** 권한 서버, 입력 명령/스냅샷, 예측/보정, 서버 명중 판정, 인벤토리 거래 권한, 재접속, 세션 종료, 인증/프로필 저장을 설계한다. 먼저 2인 협동으로 검증하고 6~8인 목표는 서버 부하/대역폭/지연 측정 후 적용한다. 실시간 사용자 시장도 이 단계에 속한다.

**완료:** 두 클라이언트가 같은 아이템을 동시에 가져갈 수 없고 탄약/치료/정산을 클라이언트 값으로 확정하지 않는다. 지연·패킷 손실·서버 종료·재접속 후 상태가 수렴한다. 이 단계 전에는 “멀티플레이 지원”으로 표시하지 않는다.

## 8. 단계와 완료 기준

우선순위는 P0=기존 루프 안정화, P1=싱글 핵심 경험, P2=깊이/콘텐츠, P3=온라인 확장이다. 일정은 실측 없이 산정하지 않는다.

| 단계 | 작업 | 선행 조건 | 단계 완료 기준 |
| --- | --- | --- | --- |
| A. 현재 기반 확정 | P0-01~05, P1-14 초기 검증 | 없음 | 저장 실패/사망 후 재기/카메라/수량 보존 통과 |
| B. 데이터 정리 | P1-03/05 기반, 저장 이관 | A | 아이템·무기·탄창 인스턴스의 단일 소유권 |
| C. 생존·교전 | P1-01~04/06, AI 공통 전투 | B | 부위·의료·방어·탄약이 일관된 교전 1회 |
| D. 탐색과 탈출 | P1-07~09/12/13 | C | 맵 내 전투·수색·조건부 탈출 루프 |
| E. 전리품의 목적 | P1-10/11, P2-02 초기 시설 | B~D | 팔기/납품/제작 중 선택 가능한 반복 경제 |
| F. 싱글 완성 | P2-01/03/04/05, P1-14 배포 | A~E | 새 PC에서 장시간 반복, 재기/진행/저장 검증 |
| G. 온라인 | P3-01 | F 및 서버 설계 | 2인 협동 검증 후 인원 확장 |

가장 먼저 착수할 구체적 묶음은 **사망 후 붕대가 없는 프로필 재현 → 재기 정책 구현 → 성공 정산 저장 실패 안내 → T 개발 전용화 → 반복 레이드 회귀 확인**이다. 총기 종류나 새 맵을 먼저 늘리는 것보다 현재 장비를 지속적으로 운용할 수 있는지 확인한다.

## 10. 기존 설계의 인계와 범위 결정

### 10.1 유지하는 자체 맵 목표

| 항목 | 현재 | 기존 설계에서 넘겨받는 목표 |
| --- | --- | --- |
| 맵 / 시간 | 500×500m / 25분 | 우선 유지 |
| 플레이어 | 로컬 1명 | 온라인 단계에서 6~8명 검토 |
| AI | 초기 5명, 추가 생성 없음 | 초기 10, 동시 최대 12, 누적 20 |
| 스폰 | 2개 | 후보 12~16, 기본 목표 16 |
| 스폰 안전 | 무작위 선택 | 권장 간격 120m, 중앙과 80m, 20m 이내 엄폐; 조건 미충족 예외 기록 |
| 탈출 | 기본 2개 | 기본 2+조건부 2 |
| 루팅 | 20곳 | 목표 100, 설계 범위 90~120 |
| 건물 | 주요 단층 5개 | 진입 9~12, 공장/관리동 2층 |
| 구역 AI 목표 | 5좌표 | 창고 2·야적장 2·공장 3·관리동 1·발전소 2 |
| 동선 지표 | 미측정 | 첫 교전 2~5분, 2~3분마다 탐색/위험 접점이라는 가설 검증 |

이 수치들은 `RaidConfig.h`에 일부 상수로 존재하지만 상수가 있다는 사실은 스폰 알고리즘·멀티플레이·AI 증원·조건부 출구 구현을 뜻하지 않는다. 120m 간격은 작은 맵에서 8인 모두에 보장된다는 의미도 아니다.

### 10.2 먼저 결정할 규칙

- **원작 충실도:** 440HP와 세부 의료를 채택할지, 더 간단한 자체 규칙을 유지할지. 어느 쪽이든 UI/코드/문서를 일치시킨다.
- **카메라:** 1인칭 전술 게임을 기준으로 할지, 현재 3인칭도 정식 모드로 지원할지. 시야 이득과 AI 난이도에 영향을 준다.
- **의류와 장비:** 현재 속옷·겉옷까지 전리품인 자체 요소를 유지할지, 외형과 성능 슬롯을 분리할지. 원작 의류 체계와 같다고 가정하지 않는다.
- **보험/안전 컨테이너:** 싱글플레이 기본 규칙에 넣을지, 선택 난이도로 제공할지.
- **오프라인 시간:** 회복·제작·Scav 대기를 종료 중에도 진행할지. 현재 레이드 타이머와 다른 시계가 필요하다.
- **온라인 범위:** 기존 6~8인 설계는 확장 목표이며 싱글 완성의 선행 조건이 아니다.

기존 문서의 “아이템 사용·버리기/AI/저장을 다음에 구현” 항목은 이미 코드가 있으므로 새 작업으로 중복하지 않는다. 이전 BUILD/STRUCTURE/VALIDATION 및 각 기능 설명은 [개발된 내용](IMPLEMENTED.md)에 통합했고, COMPLETION_SPEC/NEXT_TASK_SPEC/MAP01_DESIGN의 유효한 미완료 항목은 이 문서로 인계했다.
