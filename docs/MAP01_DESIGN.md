# Project Tarkov — Map 01 레이드 설계 문서

> **문서 버전:** v0.1  
> **맵 이름:** Industrial Zone (폐쇄 산업단지)  
> **개발 환경:** C++17 / OpenGL / GLFW / GLAD / GLM / Assimp  
> **설계 상태:** 맵 크기·레이드 시간·플레이 스타일 확정, 세부 수치 테스트 예정

---

## 1. 프로젝트 개요

Project Tarkov는 교전, 탐색, 루팅, 탈출을 중심으로 하는 FPS 익스트랙션 슈터 게임이다.

첫 번째 맵은 폐쇄된 산업단지를 배경으로 하며, 플레이어는 제한시간 내에 장비와 물자를 확보하고 지정된 탈출구를 통해 생존해야 한다.

### 1.1 확정 설정

| 항목 | 설정 |
|---|---|
| 맵 이름 | Industrial Zone (임시) |
| 맵 크기 | **500m × 500m** |
| 맵 면적 | 250,000m² (0.25km²) |
| 레이드 제한시간 | **25분 (1,500초)** |
| 플레이 스타일 | **교전·탐색·루팅 균형** |
| 목표 평균 플레이 시간 | 15~20분 |
| 월드 단위 | 1 Unit = 1m |
| 월드 중심 | (0, 0, 0) |
| 월드 X/Z 범위 | -250m ~ +250m |

### 1.2 초기 밸런스 목표

| 항목 | 초기 목표 |
|---|---|
| 플레이어 | 6~8명 |
| 동시 활성 AI | 8~12명 |
| 누적 AI 스폰 상한 | 20명 |
| 스폰 후보 | 12~16개 |
| 탈출구 | 4개 |
| 진입 가능한 건물 | 9~12개 |
| 루팅 포인트 | 90~120개 |
| 목표 콘텐츠 비중 | 교전 40% / 탐색 30% / 루팅 30% |

**참고:** 플레이어 수, AI 수, 건물 수, 루팅 확률 등은 초기 설계값이며 실제 테스트를 통해 조정한다.

## 2. 맵 구조 설계

### 2.1 맵 콘셉트

**Industrial Zone — 폐쇄 산업단지**

산업단지 중앙에 공장을 배치하고 주변에 창고, 컨테이너 야적장, 관리동, 발전소를 배치한다.

외곽에는 숲, 폐도로, 배수로, 폐차량 등을 배치해 우회 이동과 저위험 루팅이 가능하도록 설계한다.

### 2.2 주요 구역

| ID | 구역 | 주요 구조물 | 위험도 | 주요 루팅 |
|---|---|---|---|---|
| A | 창고 구역 | 대형 창고 2개, 소형 사무실 | 중간 | 식량, 공구, 잡화 |
| B | 컨테이너 구역 | 컨테이너 35~45개 | 중간 | 탄약, 무기 부품 |
| C | 중앙 공장 | 2층 공장, 부속 건물 2개 | 매우 높음 | 고급 장비, 희귀 부품 |
| D | 관리동 | 2층 사무실, 경비실 | 중간 | 의약품, 문서, 열쇠 |
| E | 발전소 | 발전 시설, 창고 | 높음 | 전자 부품, 연료 |
| F | 외곽 구역 | 숲, 폐도로, 배수로 | 낮음~중간 | 일반 보급품 |

### 2.3 건물 밀도

- 진입 가능한 건물: 9~12개
- 소형 구조물 및 엄폐물: 60~90개
- 주요 실내 공간: 25~35개
- 건물 바닥 점유율: 맵 전체 면적의 약 10~15%
- 전체 루팅 포인트: 90~120개

### 2.4 맵 설계 원칙

1. 중앙 공장은 가장 위험하지만 보상이 높은 지역으로 설계한다.
2. 외곽은 상대적으로 안전하지만 루팅 보상을 낮게 설정한다.
3. 주요 건물에는 복수의 진입 및 탈출 경로를 제공한다.
4. 한 위치에서 주요 이동 경로 전체를 통제할 수 없도록 엄폐물과 지형을 배치한다.
5. 플레이어가 2~3분마다 탐색 장소 또는 교전 위험을 마주하도록 동선을 설계한다.
6. 스폰 지점과 탈출구 사이에 여러 이동 경로를 제공한다.

## 3. 플레이어 스폰 시스템

### 3.1 기본 규칙

| 항목 | 설정 |
|---|---|
| 스폰 후보 수 | 12~16개 |
| 권장 스폰 간 거리 | 120m 이상 |
| 중앙 공장과의 거리 | 최소 80m |
| 스폰 인근 엄폐물 | 20m 이내 |
| 스폰 직후 무적시간 | 없음 |
| 예상 첫 교전 | 시작 후 2~5분 |

120m는 우선 적용할 권장 거리이며, 8명 배치 시 모든 스폰에서 보장되지는 않을 수 있다.

### 3.2 스폰 배치 규칙

스폰 지점은 맵 외곽에 분산 배치한다.

- S1: 남서쪽 외곽
- S2: 북서쪽 창고 인근
- S3: 동쪽 숲길
- S4: 남동쪽 폐도로

각 구역에 여러 스폰 후보를 두고 실제 레이드 시작 시 적절한 위치를 선택한다.

### 3.3 스폰 선택 알고리즘

1. 스폰 후보를 수집한다.
2. 지형과 엄폐물 유무를 확인한다.
3. 이미 선택된 스폰과 거리를 비교한다.
4. 다른 플레이어와 직접 시야가 연결되는지 확인한다.
5. 예상 이동 경로의 중첩 정도를 평가한다.
6. 가장 안전한 후보를 선택한다.

### 3.4 스폰 데이터 구조

```cpp
struct SpawnPoint
{
    glm::vec3 position;
    float safetyScore;
    int regionId;
};
```

## 4. 탈출구 시스템

### 4.1 탈출구 목록

| ID | 이름 | 탈출 조건 | 탈출 소요시간 |
|---|---|---|---|
| X1 | 북동쪽 검문소 | 먼 지역에서 스폰한 플레이어에게 개방 | 8초 |
| X2 | 남동쪽 폐도로 | 먼 지역에서 스폰한 플레이어에게 개방 | 8초 |
| X3 | 서쪽 배수로 | 열쇠 소지 또는 발전기 가동 | 12초 |
| X4 | 남쪽 화물차 | 레이드당 1회 사용, 작동 후 60초 대기 | 10초 |

### 4.2 탈출 규칙

1. 플레이어는 자신의 스폰 위치에 따라 기본 탈출구를 배정받는다.
2. 스폰 지점과 가까운 기본 탈출구는 비활성화한다.
3. 조건부 탈출구는 해당 조건을 충족해야 사용할 수 있다.
4. 플레이어가 탈출 범위에 들어가면 카운트다운이 시작된다.
5. 탈출 범위를 벗어나면 카운트다운이 초기화된다.
6. 탈출 도중 피해를 입더라도 범위 안에 있으면 카운트다운은 유지된다.
7. 제한시간이 끝나기 전에 탈출을 완료해야 한다.

### 4.3 탈출 결과

| 상황 | 결과 |
|---|---|
| 정상 탈출 | 생존, 획득 아이템 보존 |
| 사망 | 레이드 실패, 장비 손실 |
| 시간 초과 | MIA 처리, 레이드 실패 |
| 탈출 중 제한시간 종료 | 탈출 실패 |
| 모든 AI 처치 | 레이드 계속 진행 |

초기 버전에서는 보험, 안전 컨테이너, 팀원 장비 회수 등 복잡한 예외 규칙은 제외한다.

## 5. AI 시스템

### 5.1 AI 수량

- 초기 배치: 10명
- 동시 활성 목표: 8~12명
- 누적 스폰 상한: 20명

### 5.2 구역별 초기 AI 배치

| 구역 | AI 수 |
|---|---:|
| 창고 | 2 |
| 컨테이너 | 2 |
| 중앙 공장 | 3 |
| 관리동 | 1 |
| 발전소 | 2 |
| **합계** | **10** |

### 5.3 AI 유형

**일반 AI**

- 구역 순찰
- 주변 소리에 반응
- 플레이어 발견 시 교전

**경비 AI**

- 주요 건물 및 출입구 방어
- 제한된 구역에서 경계
- 적 발견 시 엄폐 후 교전

**강화 AI**

- 중앙 공장 등 고가치 구역 방어
- 일반 AI보다 높은 전투 능력
- 고급 장비 드롭 가능

### 5.4 AI 리스폰 규칙

- 플레이어가 가까이 있는 위치에서는 리스폰 금지
- 플레이어 시야 안에서는 리스폰 금지
- 구역별 AI 상한 적용
- 전체 동시 활성 AI 상한 적용
- 필요 시 멀리 있는 AI의 업데이트 빈도 감소

## 6. 루팅 시스템

### 6.1 루팅 포인트

| 항목 | 설정 |
|---|---|
| 전체 루팅 포인트 | 약 100개 |
| 레이드당 활성 포인트 | 60~75개 |
| 아이템 생성 방식 | 확률 기반 |
| 고가치 루팅 지역 | 중앙 공장, 발전소 |
| 저위험 루팅 지역 | 외곽, 일반 창고 |

### 6.2 아이템 희귀도

| 등급 | 기본 확률 |
|---|---:|
| 일반 | 55% |
| 고급 | 28% |
| 희귀 | 13% |
| 최상급 | 4% |
| **합계** | **100%** |

위 확률은 기본 아이템 풀의 초기 설정이다. 실제 생성 시에는 구역과 컨테이너 종류에 따라 가중치를 조정한다.

### 6.3 루팅 밸런스 원칙

1. 안전한 지역은 평균 보상을 낮게 설정한다.
2. 위험한 지역은 희귀 아이템 출현 확률을 높인다.
3. 모든 아이템이 매 판 같은 위치에 생성되지 않도록 한다.
4. 특정 구역만 반복 방문하는 것이 항상 최적의 선택이 되지 않도록 한다.
5. 루팅 도중 주변 경계가 필요하도록 컨테이너 상호작용 시간을 설정한다.

## 7. 레이드 시간 설계

### 7.1 총 플레이 시간

**25분 = 1,500초**

| 구간 | 주요 활동 |
|---|---|
| 0~5분 | 스폰, 초기 이동, 저위험 루팅 |
| 5~15분 | 주요 구역 탐색, 교전, 고가치 루팅 |
| 15~20분 | 전리품 정리, 추가 탐색, 탈출 판단 |
| 20~25분 | 탈출 이동, 마지막 교전, 시간 압박 |

### 7.2 시간 종료 규칙

- 레이드 타이머는 시작 시 1,500초로 설정한다.
- 매 프레임 `deltaTime`을 차감한다.
- 남은 시간이 0초가 되면 레이드가 종료된다.
- 탈출하지 못한 플레이어는 MIA로 처리한다.
- 탈출 성공 여부와 획득 아이템은 레이드 결과 화면에 전달한다.

### 7.3 레이드 타이머 구현 예시

```cpp
// RaidConfig.h
#pragma once

namespace RaidConfig
{
    constexpr float MapWidth = 500.0f;
    constexpr float MapLength = 500.0f;

    constexpr float RaidDuration = 25.0f * 60.0f;
}
```

```cpp
// RaidScene.h
float raidTimeRemaining = RaidConfig::RaidDuration;
bool raidEnded = false;
```

```cpp
// RaidScene.cpp
void RaidScene::Update(float dt)
{
    if (raidEnded)
        return;

    raidTimeRemaining -= dt;

    if (raidTimeRemaining <= 0.0f)
    {
        raidTimeRemaining = 0.0f;
        raidEnded = true;

        // TODO: MIA 처리
        // TODO: 레이드 결과 화면으로 전환
        return;
    }

    // 기존 플레이어, 카메라, AI 업데이트
}
```

기존 `RaidScene::Update()`의 이동 및 카메라 처리 코드는 유지하고 타이머 로직만 통합한다.

## 8. 플레이어 이동속도 및 이동시간

### 8.1 이동속도

| 상태 | 이동속도 |
|---|---:|
| 걷기 | 3m/s |
| 달리기 | 6m/s |
| 앉기 | 추후 결정 |
| 조준 이동 | 추후 결정 |

### 8.2 거리별 이동시간

| 거리 | 걷기 | 달리기 |
|---|---|---|
| 100m | 약 33초 | 약 17초 |
| 250m | 약 1분 23초 | 약 42초 |
| 500m | 약 2분 47초 | 약 1분 23초 |
| 700m | 약 3분 53초 | 약 1분 57초 |

위 수치는 장애물이 없는 직선 이동 기준이다.

실제 레이드에서는 엄폐 이동, 건물 탐색, 스태미나, 교전으로 인해 이동시간이 증가한다.

## 11. 첫 번째 플레이 가능 버전(MVP)

첫 번째 플레이 가능 버전은 전체 시스템을 한 번에 구현하지 않는다.

### MVP 구현 범위

| 시스템 | MVP 목표 |
|---|---|
| 맵 | 500m × 500m 블록아웃 |
| 건물 | 핵심 건물 5개 |
| 플레이어 | 1명 |
| AI | 3~5명 |
| 스폰 | 고정 스폰 2개 중 선택 |
| 탈출구 | 기본 탈출구 2개 |
| 루팅 | 20개 포인트 |
| 인벤토리 | 기본 아이템 획득 및 보관 |
| 레이드 시간 | 25분 |
| 결과 처리 | 탈출 성공 / 사망 / MIA |

### MVP 완료 기준

1. 플레이어가 맵에 스폰한다.
2. 건물과 지형을 탐색한다.
3. 아이템을 획득한다.
4. AI와 교전할 수 있다.
5. 지정된 탈출구까지 이동한다.
6. 25분 안에 탈출하면 성공한다.
7. 사망하거나 시간이 종료되면 실패한다.
8. 레이드 결과를 확인할 수 있다.

## 12. 최종 설계 방향

Project Tarkov의 첫 번째 맵은 **500m × 500m / 25분**을 기준으로 제작한다.

게임의 핵심 경험은 다음 순서로 구성한다.

**스폰 → 탐색 → 루팅 → 교전 → 위험 판단 → 탈출**

중앙 지역에서는 높은 보상과 교전 위험을 제공하고, 외곽에서는 상대적으로 안전한 이동과 낮은 보상을 제공한다.

첫 번째 개발 목표는 정교한 그래픽보다 **실제 플레이 가능한 맵 구조와 레이드 흐름 검증**에 둔다.

이후 테스트 결과를 기반으로 AI 수, 루팅 밀도, 탈출구 조건, 평균 플레이 시간을 조정한다.
