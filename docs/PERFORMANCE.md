# 성능 개선 적용 내역

2026-10-08. 요청에 따라 소스만 저장했으며 빌드·게임 실행·FPS 측정은 하지 않았습니다.

| 우선순위 | 적용 내용 |
| --- | --- |
| 1 | 일반 캐릭터 프레임은 GPU 스키닝. CPU는 본 계층·포즈·법선 행렬만 계산하고 재사용 버퍼에 저장. 전체 정점 복사·매 프레임 VBO 업로드 제거. |
| 2 | Assimp 동일 정점 병합, 고유 정점과 EBO를 사용하는 glDrawElements 적용. |
| 3 | 모델·FBX 클립·캐릭터 메시·가중치·캐릭터 모션 클립 공유. 포즈·시간·전환·사망 상태·본 행렬은 캐릭터별로 유지. |
| 4 | 현재 포즈의 본별 경계를 변환해 시야 밖 캐릭터와 무기 렌더링 제외. 적의 포즈는 카메라 거리 25m 초과 시 최대 30Hz, 60m 초과 시 최대 15Hz로 갱신. |
| 5 | uniform 위치 캐시. 셰이더 재링크 성공 시 캐시 무효화. 카메라·조명·공통 sampler는 PrepareFrame에서 프레임당 한 번 설정. |
| 6 | 셰이더 변경 확인은 Debug에서 500ms 간격으로 수행. Release에서는 변경 확인 생략. 컴파일 실패 시 기존 프로그램 유지. |

## 동작과 수명

- OpenGL 3.3 Core 컨텍스트를 요청합니다. cube.vs와 C++ 렌더링 변경은 함께 사용해야 합니다. 기존 실행 파일과 새 셰이더만 혼합하면 안 됩니다. 소스 에셋은 다음 정상 빌드의 CopyRuntimeAssets 단계에서 복사됩니다.
- 가중치 텍스처 버퍼는 texture unit 6, 캐릭터별 본 행렬 텍스처 버퍼는 unit 7을 사용합니다. 각 본은 변환 mat4와 법선 mat4를 차례로 저장합니다. 가중치를 4개로 자르지 않고 모두 정규화해 유지합니다. 버퍼 용량이 GPU의 GL_MAX_TEXTURE_BUFFER_SIZE를 초과하면 명시적 로드 오류를 냅니다.
- 공유 에셋 캐시는 약한 참조를 사용합니다. 마지막 캐릭터가 Reset되면 공유 GPU 자원도 해제되며, 장면 종료는 컨텍스트 파괴 전에 수행됩니다. 현재 로딩은 메인 스레드 기준입니다.
- CPU 정점 변형은 사망 동작의 정확한 바닥 보정에만 남아 있습니다. 시체의 마지막 자세는 갱신 없이 유지합니다.
- 시야 판정은 본별 정점 경계의 합집합을 사용하며 무기·탄창·화염을 위해 월드 공간 2m 여유를 둡니다. 무기 크기나 이동 범위를 확장하면 이 여유도 검토해야 합니다.
- 거리별 갱신 제한은 시각 포즈에만 적용됩니다. AI, 물리, 명중, 생존 상태와 총기 이벤트는 매 프레임 처리합니다. 사망 포즈는 거리 제한 없이 갱신합니다. 낮은 포즈 갱신률에서 보간은 추가하지 않았습니다.
- 프레임 공통 데이터는 HUD가 렌더링되기 전에 설정합니다. 새 렌더 패스나 다른 셰이더를 추가하면 해당 패스의 PrepareFrame 호출도 필요합니다.

## 검증 범위와 다음 실행 확인

소스 호출 관계, 자원 이동·해제, 셰이더와 버퍼 레이아웃을 정적으로 점검했습니다. git diff --check와 변경 파일의 UTF-8·로컬 include 경로 확인을 통과했습니다. 별도 Python 수치 점검에서 행렬 전달·가중치 혼합·본 경계의 보수성을 1,000개 사례로, 시야 판정은 화면 안·밖·경계 사례로 확인했습니다. 이는 C++/GLSL 실행 검증이 아니며 컴파일 성공·GPU 실행 결과·성능 향상 수치는 아직 확인하지 않았습니다.

다음 실행에서는 이동·웅크리기·재장전·사망 포즈와 조명, 캐릭터 간 독립 애니메이션, 카메라 회전 시 화면 가장자리의 무기 표시, 장면 종료·재진입, Debug 셰이더 재로드 성공·실패를 확인하세요. 성능은 같은 해상도와 적 수에서 Release 프레임 시간 및 CPU/GPU 시간을 비교해야 합니다.
