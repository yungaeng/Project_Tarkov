# 맵 데이터 편집

`src/Game/World/HideoutLayout.cpp`, `IndustrialLayout.cpp`가 읽는 공백 구분 텍스트다. UTF-8로 저장하고 `#`로 시작하는 주석 행과 빈 행을 사용할 수 있다. 길이는 미터, 회전은 도 단위, 색은 RGB 값이다. 데이터는 프로세스 내에서 캐시하므로 편집 후 게임을 다시 시작한다. 셰이더의 핫 리로드와는 별개다.

## 은신처 가구 배치: Hideout/room.layout

한 행: `prefab x z storageId radius [room]`

예: `medicalTable 1.2 -2.5 3 1.7`

- x는 각 방 왼쪽 기준, z는 은신처 좌표다. 방 번호는 코드에서 0부터 시작하고 가로 간격은 6m다.
- storageId는 0=냉장고, 3=의료품 탁자, 4=일반 창고를 여는 펠리컨 케이스, -1=보관함 없음이다. 이전 저장 데이터의 1=무기고, 2=옷장 ID는 유지하지만 배치하지 않으며, 내용물은 일반 창고로 이관한다.
- room은 생략하거나 -1이면 모든 방, 0이면 1번 방에만 배치한다. 펠리컨 케이스는 `pelicanCase 3.65 -6.8 4 1.8 0`으로 1번 방에만 배치한다.
- radius는 수평 상호작용 거리다. 보관 가구는 1.7m, 침대 자세 상호작용은 기존 1.5m를 유지한다. 의자는 0이다.
- medicalTable, pelicanCase, refrigerator, bed, chair 다섯 이름이 필요하다. 같은 이름 또는 보관함 ID의 중복은 허용하지 않는다.
- 위치 데이터는 렌더링과 상호작용에서 함께 사용한다. 각 가구의 모양은 `Prefabs/<prefab>.parts`에 있다.

## 가구 구성: Hideout/Prefabs/*.parts

한 행: `condition anchor solid shape px py pz sx sy sz r g b rx ry rz`

- condition: `always` 또는 `blanket`. blanket은 침대 자세 동작 중 이불을 숨기는 용도다.
- anchor: `local`은 가구 위치에 상대적이다. `wall`은 x에 가구 위치를 적용하지만 z는 가구 위치를 더하지 않는 고정 벽 장식이다.
- solid: 0=표시만, 1=충돌 포함. 충돌은 축 정렬 박스이므로 solid=1의 회전은 0이어야 한다.
- shape: 0=박스, 1=원기둥, 2=원뿔, 3=바위형 기본 도형.
- p는 중심, s는 전체 크기, RGB는 색, 마지막 세 값은 시각 회전이다. 크기는 양수여야 한다.

기존 가구의 90% 크기 보정은 파일에 이미 반영했다. 로더에서 다시 0.9를 곱하지 않는다. 침대의 수면 높이와 자세 지지 영역은 아직 `HideoutScene.cpp`에 있으므로 침대 치수를 바꾸는 작업에는 그 계산도 함께 반영해야 한다.

## 은신처 구조: Hideout/shell.layout

한 행: `stateBits collision shape px py pz sx sy sz r g b rx ry rz`

collision은 0=표시만, 1=표시와 충돌, 2=보이지 않는 충돌 경계다. 나머지 도형 값은 가구 구성과 같다. 위치는 은신처 절대 좌표다.

stateBits는 현재 3·4번 방의 개방 상태별 표시 비트다. 상태 0=둘 다 잠김, 1=3번만 열림, 2=4번만 열림, 3=둘 다 열림이며, 해당 상태의 `1 << 상태` 값을 합한다. 따라서 15는 항상 표시, 5는 3번 방이 잠겼을 때 표시, 10은 3번 방이 열렸을 때 표시한다. 방 개방 규칙 자체는 프로필 로직에 남아 있다.

벽·난간·문·창·장식·낙하 방지 충돌을 편집할 수 있다. 단, 방 수·방 간격·카메라 구역·레이드 출입 조건은 여전히 게임 코드와 연결되므로 건물 전체 크기를 바꿀 때 shell 파일만 변경해서는 안 된다.

## 산업단지 위치: IndustrialZone/locations.layout

한 행: `kind index x y z`

kind는 spawn(2개), exit(2개), building(5개), enemy(5개)다. index는 각 종류별 0부터 시작한다. 총 14개 위치가 모두 있어야 하며 중복·범위 밖 인덱스는 오류다. 북쪽은 -Z다.

이 파일은 주요 위치를 지정한다. 건물 외형·도로·컨테이너·수풀 등을 만드는 절차적 생성 규칙은 `IndustrialZone.cpp`, `IndustrialDetails.cpp`에 남아 있다. 이 파일만으로 산업단지의 모든 오브젝트를 편집할 수 있는 것은 아니다.

## 변경 시 유의점

이름 누락·중복·잘못된 도형 번호·음수 크기 등은 로딩 오류가 된다. 파서는 전용 텍스트 형식이므로 JSON이나 CSV로 바꾸지 않는다. 변경한 데이터의 동선·충돌·카메라·상호작용은 별도 실행 확인이 필요하며, 이번 문서 정리에서는 게임을 실행하지 않았다.
